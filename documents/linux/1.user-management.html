Linux User Management

Complete Ubuntu User Administration Guide with Practical Commands

1. Introduction to Linux User Management

Linux is a multi-user operating system. Multiple users can access the same Linux system using separate accounts. Each user has an identity, a username, a unique user ID, group memberships and account settings.

Linux user management is the process of creating, modifying, configuring and deleting user accounts. It also involves managing passwords, groups, login shells and administrative privileges.

Why is user management important?

  • Security: Control who can access the system.
  • Access control: Provide appropriate access to users.
  • Accountability: Identify users through their individual accounts.
  • Administration: Manage multiple users centrally.
  • Isolation: Maintain separate user environments.

Example scenario

Consider a company with three employees:

  • David - Developer
  • John - System Administrator
  • Sarah - Database Administrator

The Linux administrator creates individual accounts for these employees. Each employee uses their own username and password to access the system. The administrator can assign different groups and privileges depending on their responsibilities.

2. Types of Linux Users

2.1 Root User

The root user is the superuser account in Linux. It has UID 0 and has administrative privileges across the system.

Root can perform operations such as:

  • Creating and deleting user accounts.
  • Installing and removing software.
  • Managing system services.
  • Changing system configurations.
  • Managing other users and groups.
# Check current username
whoami

# Check root account details
id root

# Display root account information
getent passwd root

2.2 Regular User

A regular user is an account created for normal system usage. Regular users have their own UID, home directory and login shell. They generally have limited administrative privileges. 

# Create a regular user
adduser david

# Switch to David
su - david

# Verify current user
whoami

2.3 System User

System users are generally created for operating system services and applications. They allow a service to run under a dedicated account instead of running everything as root. 

# Create a system user
useradd --system \
  --no-create-home \
  --shell /usr/sbin/nologin \
  appservice

# Verify account
id appservice

# Display account information
getent passwd appservice

2.4 Understanding UID Ranges

Every Linux user has a User ID (UID). Linux uses this numeric identifier internally to distinguish users.

UID Typical purpose
0 Root account
1-999 Common system account range on Ubuntu
1000 and above Common regular user range on Ubuntu

These ranges are configurable. You can check the actual values configured on your system. 

grep -E '^(UID_MIN|UID_MAX|SYS_UID_MIN|SYS_UID_MAX)' /etc/login.defs

3. Linux User Management Configuration Files

Linux maintains account and group information in specific configuration files. Understanding these files is important for system administration and troubleshooting.

3.1 /etc/passwd

The /etc/passwd file contains user account information. It includes the username, UID, primary GID, descriptive information, home directory and login shell. 

# Display all user accounts
cat /etc/passwd

Example entry:

david:x:1000:1000:David:/home/david:/bin/bash
FieldValueDescription
1davidUsername
2xPassword information is stored separately
31000User ID (UID)
41000Primary Group ID (GID)
5DavidComment or descriptive information
6/home/davidHome directory
7/bin/bashLogin shell

3.2 /etc/shadow

The /etc/shadow file stores password hashes and password-aging information. Access is restricted because it contains sensitive authentication data. 

# Check file permissions
ls -l /etc/shadow

# Read as an authorized administrator
sudo cat /etc/shadow

Example structure:

david:$y$j9T$examplehash:20000:0:99999:7:::
FieldDescription
UsernameAccount name
Password hashHashed password or account marker
Last changeDay the password was last changed
MinimumMinimum number of days before another password change
MaximumMaximum password age in days
WarningDays before expiry to warn the user
InactiveDays after password expiry before disabling the account
ExpireAccount expiration date

3.3 /etc/group

The /etc/group file stores local group information. It contains the group name, GID and supplementary group members. 

# Display all groups
cat /etc/group

Example:

developers:x:1002:david,john
FieldDescription
developersGroup name
xGroup password field placeholder
1002Group ID (GID)
david,johnSupplementary group members

3.4 /etc/gshadow

The /etc/gshadow file stores protected group information, including group administrators and group password data. 

sudo cat /etc/gshadow

3.5 /etc/skel

The /etc/skel directory contains default files that are copied into a new user's home directory when the account is created with home-directory initialization. 

# View skeleton directory contents
ls -la /etc/skel

For example, files such as .profile and .bashrc may be copied into the new user's home directory.

5. Understanding adduser and useradd

Ubuntu provides two commonly used commands for creating users: adduser and useradd. Both create accounts, but their interfaces and default behavior are different.

5.1 adduser

adduser is a higher-level Ubuntu utility. It normally creates a home directory, copies default files from /etc/skel and asks for a password and user information.

Create David interactively

adduser david

The command normally asks for:

  • New password.
  • Password confirmation.
  • Full name.
  • Room number.
  • Work phone.
  • Home phone.
  • Other descriptive information.

Create David without information prompts

adduser --disabled-password --gecos "" david

This creates the account and its home directory without asking for the password or descriptive information.

Set David's password separately

passwd david

Set a password non-interactively

echo 'david:YourStrongPassword' | chpasswd
Replace the example password with a strong password. Avoid placing real passwords directly in shell commands because they may be retained in command history or exposed through process information.

5.2 useradd

useradd is a lower-level account creation utility. It is commonly used in scripts and automated configuration.

Create David

useradd david

Without the -m option, the home directory is generally not created.

Create David with a home directory

useradd -m david

Create David with a Bash login shell

useradd -m -s /bin/bash david

Set the password

passwd david

5.3 Difference between adduser and useradd

Featureadduseruseradd
TypeHigher-level utilityLower-level utility
InteractionInteractive by defaultUses command-line options
Home directoryNormally created automaticallyUse -m to create it
Default filesCopies files from /etc/skelWith -m, initializes from the skeleton directory
AutomationSupports non-interactive optionsCommonly used in scripts
Do not execute both commands for the same username. If David already exists, check the account using id david before trying to create it again.

6. Creating and Managing User Accounts

6.1 Create a user with adduser

adduser david

6.2 Create a user without interactive prompts

adduser --disabled-password --gecos "" david

6.3 Create a user with a specific home directory

useradd -m -d /data/users/david david

The -d option specifies the home directory path. The -m option creates that directory and initializes it with files from the skeleton directory.

6.4 Create a user with a specific shell

useradd -m -s /bin/bash david

6.5 Create a user with a specific UID and group

groupadd developers

useradd -m -u 1500 -g developers -s /bin/bash david

6.6 Check whether a user exists

id david
getent passwd david

If the account exists, these commands display its identity and account information. If it does not exist, they will not return a valid account entry.

6.7 List all local users

cat /etc/passwd

Display only usernames

cut -d: -f1 /etc/passwd

7. Home Directory Management

A home directory is the personal directory associated with a user. It normally stores personal files, configuration files and user-specific data.

For David, the default home directory is:

/home/david

7.1 Create a home directory automatically

useradd -m david

The -m option tells useradd to create the home directory. It also initializes the directory using files from the skeleton directory.

7.2 Verify the home directory

ls -ld /home/david
ls -la /home/david

7.3 Check the configured home directory

getent passwd david

7.4 Create a missing home directory

If an account was created without the -m option, the account may exist without a home directory. 

mkdir -p /home/david
usermod -d /home/david david
chown david:david /home/david

7.5 Change a user's home directory

usermod -d /data/david -m david

The -d option changes the home directory setting. The -m option moves existing home-directory contents to the new location.

7.6 Understand the home directory entry

getent passwd david

The home directory is the sixth field in the account entry. For example, /home/david tells Linux where David's home directory is configured.

8. Understanding UID and GID

8.1 What is UID?

UID stands for User ID. It is a numeric identifier assigned to each Linux user account. Linux uses the UID internally to identify the owner of processes and files. 

# Display David's UID and GID
id david

# Display only UID
id -u david

# Display username
id -un david

8.2 What is GID?

GID stands for Group ID. It identifies a Linux group. Every user has a primary group and can also belong to additional groups. 

# Display primary group ID
id -g david

# Display primary group name
id -gn david

# Display all group memberships
id -Gn david

8.3 Understanding id output

uid=1000(david) gid=1000(david) groups=1000(david),27(sudo),1002(developers)

This means:

  • David's UID is 1000.
  • David's primary GID is 1000.
  • David belongs to the sudo group.
  • David also belongs to the developers group.

8.4 Assign a specific UID

useradd -m -u 1500 david

The -u option specifies the UID. Ensure the UID is not already assigned to another account.

8.5 Assign a specific primary group

groupadd developers
useradd -m -g developers david

The -g option assigns an existing group as the user's primary group.

9. Linux Group Management

A group is a collection of users. Groups make it easier to organize accounts and manage access to shared resources.

9.1 Create a group

groupadd developers

9.2 Create another group

groupadd administrators

9.3 View all groups

cat /etc/group

9.4 View a specific group

getent group developers

9.5 Add David to a supplementary group

usermod -aG developers david

The -a option means append, and -G specifies supplementary groups.

Always use -aG when adding a supplementary group. Using -G without -a replaces the user's existing supplementary group list.

9.6 Add David to multiple groups

usermod -aG developers,administrators david

9.7 Check group membership

groups david
id david

9.8 Remove David from a group

gpasswd -d david developers

9.9 Change the primary group

usermod -g administrators david

9.10 Delete a group

groupdel developers

A group cannot normally be deleted while it is the primary group of an existing user.

10. Primary Groups and Supplementary Groups

10.1 Primary Group

Every user has one primary group. When a user creates a new file, the file normally inherits the user's primary group, subject to the directory and system configuration.

10.2 Supplementary Groups

A user can belong to multiple supplementary groups. These groups provide additional access to resources.

10.3 Example

# Create groups
groupadd developers
groupadd testers

# Create David
useradd -m -s /bin/bash david

# Add supplementary groups
usermod -aG developers,testers david

# Check memberships
id david

David now has a primary group and additional supplementary groups.

11. Sudo and Administrative Privileges

The sudo command allows an authorized user to execute specific commands with another user's privileges, commonly root privileges. It provides controlled administrative access without requiring users to log in directly as root.

11.1 Install sudo

apt-get update
apt-get install -y sudo

11.2 Add David to the sudo group

usermod -aG sudo david

11.3 Verify group membership

groups david

11.4 Switch to David

su - david

11.5 Execute a command using sudo

sudo whoami

Expected output when sudo is configured correctly:

root

11.6 Execute administrative commands

sudo apt-get update
sudo apt-get install curl

11.7 Check sudo permissions

sudo -l

This displays the commands the current user is permitted to execute through sudo.

11.8 Configure sudo permissions

The sudoers configuration defines who can execute which commands. Use visudo to edit the configuration because it validates the syntax before saving. 

visudo

Example rule:

david ALL=(ALL:ALL) ALL

This permits David to execute commands as any user or group on the system, subject to the configured authentication requirements.

Do not edit sudoers directly with a normal text editor. Use visudo to avoid syntax errors that could prevent administrative access.

12. Password Management

Linux uses password hashes for authentication. Password-related information is maintained in the protected shadow database.

12.1 Set a password

passwd david

12.2 Change your own password

passwd

12.3 Set a password non-interactively

echo 'david:YourStrongPassword' | chpasswd

12.4 Lock a user's password

passwd -l david

This locks password authentication for the account. It does not necessarily disable every other authentication method.

12.5 Unlock a user's password

passwd -u david

12.6 Check password status

passwd -S david

12.7 Delete a user's password

passwd -d david
Deleting a password is not the same as securely disabling an account. It may permit passwordless authentication depending on the system configuration. Avoid using it on accounts that require protection.

13. Password Aging and Account Expiration

Password aging controls how long a password remains valid and when a user must change it. Account expiration controls when an account becomes invalid.

13.1 View password aging information

chage -l david

13.2 Set maximum password age

chage -M 90 david

This sets the maximum password age to 90 days.

13.3 Set minimum password age

chage -m 7 david

David must wait at least seven days before changing the password again.

13.4 Set password expiry warning

chage -W 7 david

This configures a warning seven days before password expiration.

13.5 Set account expiration date

chage -E 2026-12-31 david

This sets the account expiration date.

13.6 Remove account expiration

chage -E -1 david

13.7 Force a password change at next login

chage -d 0 david

13.8 View account aging information

chage -l david

14. Linux Login Shell Management

A login shell is the command interpreter started when a user logs in. It determines the command environment available to that user.

14.1 View available shells

cat /etc/shells

14.2 Check David's configured shell

getent passwd david

14.3 Change the login shell

usermod -s /bin/bash david

14.4 Switch to David

su - david

14.5 Assign a non-login shell

usermod -s /usr/sbin/nologin appservice

A non-login shell prevents normal interactive shell login. It is commonly used for service accounts that do not need interactive access.

15. Modifying Existing Users with usermod

The usermod command changes the properties of an existing Linux user account.

OptionPurpose
-lChange the username
-uChange the UID
-gChange the primary group
-GSet supplementary groups
-aGAppend supplementary groups
-dChange the home directory setting
-mMove home directory contents when used with -d
-sChange the login shell
-LLock the account password
-UUnlock the account password

15.1 Change username

usermod -l david_new david

15.2 Change UID

usermod -u 1500 david

15.3 Change primary group

usermod -g developers david

15.4 Add supplementary groups

usermod -aG developers,administrators david

15.5 Change home directory

usermod -d /data/david -m david

15.6 Change login shell

usermod -s /bin/bash david

15.7 Lock account password

usermod -L david

15.8 Unlock account password

usermod -U david
Changing a UID or username can affect existing account references and running processes. Review these dependencies before modifying production accounts.

16. Switching Between Linux Users

The su command allows you to switch from one user account to another. It is useful when testing account configuration or performing tasks under a different user identity.

16.1 Switch to David

su - david

The hyphen starts a login shell and loads David's login environment.

16.2 Check the current user

whoami

16.3 Check the current directory

pwd

16.4 Check user identity

id

16.5 Return to the previous account

exit

16.6 Execute a command as another user

su - david -c "whoami"

The -c option executes the specified command and then exits the switched-user shell.

17. Deleting Linux Users

When an account is no longer required, an administrator can remove it from the system.

17.1 Delete a user account

userdel david

This removes the account but normally retains the user's home directory.

17.2 Delete a user and home directory

userdel -r david

The -r option also removes the user's home directory and mail spool, if present.

17.3 Delete using deluser

deluser david

17.4 Delete a user and home directory using deluser

deluser --remove-home david

17.5 Verify user deletion

id david
getent passwd david

17.6 Delete an unused group

groupdel developers
Before deleting an account, check whether it is used by running services, scheduled tasks or applications. Also consider any important account data that needs to be retained.

18. Locking and Disabling User Accounts

Account locking is useful when access must be temporarily restricted. Password locking and account expiration are related but different mechanisms.

18.1 Lock password authentication

passwd -l david

18.2 Unlock password authentication

passwd -u david

18.3 Set an account expiration date

chage -E 2026-12-31 david

18.4 Check account expiration

chage -l david

18.5 Prevent interactive login

usermod -s /usr/sbin/nologin david

18.6 Restore Bash login

usermod -s /bin/bash david

Choose the appropriate control based on the requirement. Locking a password does not necessarily block SSH keys or every other authentication mechanism.

20. Common User Management Problems

Problem 1: adduser command not found

Install the required package:

apt-get update
apt-get install -y adduser

Problem 2: useradd does not create a home directory

Use the -m option:

useradd -m david

Problem 3: Home directory does not exist

For an account that already exists:

mkdir -p /home/david
usermod -d /home/david david
chown david:david /home/david

Problem 4: User cannot execute sudo

Install sudo and add the user to the sudo group:

apt-get install -y sudo
usermod -aG sudo david

Start a new login session and verify the group membership.

Problem 5: User cannot switch accounts

Check the account, home directory and login shell:

getent passwd david
ls -ld /home/david
cat /etc/shells

Problem 6: User already exists

Verify the account before attempting to create it again:

id david
getent passwd david

Problem 7: Group membership is not updated

Check David's current group membership:

id david
groups david

Start a new login session after changing supplementary group membership.

Problem 8: Password authentication is locked

Check password status:

passwd -S david

Unlock the password if appropriate:

passwd -u david
