Jenkins: Create Your First Job – Fetch Linux Host Details

In this practical exercise, you will create your first Jenkins Freestyle job. The job will execute Linux commands on the Jenkins server and collect system information such as hostname, operating system, kernel version, CPU, memory, disk space, IP address, and current user.

Prerequisites:
  • Jenkins server must be running.
  • You must be logged in to Jenkins.
  • You must have permission to create Jenkins jobs.
  • The Jenkins server must be running on Linux.
  • The Jenkins build executor must be available.

1. Understanding the Practical

Jenkins jobs allow you to automate commands and scripts. In this exercise, you will create a Freestyle project that executes Linux commands and displays the server information in the Jenkins build console.

The job will collect the following information:

Information Linux Command
Hostname hostname
Operating System cat /etc/os-release
Kernel Version uname -r
System Architecture uname -m
CPU Information nproc
Memory Information free -h
Disk Usage df -h
IP Address hostname -I
Current User whoami
System Uptime uptime
Important: This exercise executes commands on the Jenkins build executor. If your job runs on the built-in Jenkins node, the information displayed belongs to the Jenkins server/container. It does not automatically collect information from another remote Linux machine.

2. Open the Jenkins Dashboard

Step 1 Open your Jenkins URL in a web browser.
Step 2 Log in using your Jenkins credentials.
Step 3 You should now see the Jenkins Dashboard.

3. Create a New Freestyle Job

Step 1 On the Jenkins dashboard, click New Item.
Step 2 Enter the following job name: 
linux-host-details
Step 3 Select Freestyle project.
Step 4 Click OK.
Jenkins will open the configuration page for your new job.

4. Configure the Job Description

Locate the Description field under the General section. Enter the following description: 

This Jenkins job collects Linux host information,
including hostname, OS, kernel, CPU, memory,
disk usage, IP address, and system uptime.

Leave the other General settings at their default values.

5. Configure the Build Step

Now configure the shell script that will collect the Linux host information.

Step 1 Scroll down to the Build Steps section.
Step 2 Click Add build step.
Step 3 Select Execute shell.
Step 4 A shell command text area will appear.
Step 5 Copy and paste the complete script below into the text area.

Shell Script

#!/bin/bash

echo "=========================================="
echo "       LINUX HOST INFORMATION"
echo "=========================================="

echo ""
echo "1. HOSTNAME"
echo "------------------------------------------"
hostname

echo ""
echo "2. OPERATING SYSTEM"
echo "------------------------------------------"
cat /etc/os-release

echo ""
echo "3. KERNEL VERSION"
echo "------------------------------------------"
uname -r

echo ""
echo "4. SYSTEM ARCHITECTURE"
echo "------------------------------------------"
uname -m

echo ""
echo "5. CPU INFORMATION"
echo "------------------------------------------"
echo "CPU Cores: $(nproc)"
lscpu | grep -E 'Model name|CPU\(s\):' | head -n 2

echo ""
echo "6. MEMORY INFORMATION"
echo "------------------------------------------"
free -h

echo ""
echo "7. DISK USAGE"
echo "------------------------------------------"
df -h

echo ""
echo "8. IP ADDRESS"
echo "------------------------------------------"
hostname -I

echo ""
echo "9. CURRENT USER"
echo "------------------------------------------"
whoami

echo ""
echo "10. SYSTEM UPTIME"
echo "------------------------------------------"
uptime

echo ""
echo "11. JENKINS JOB INFORMATION"
echo "------------------------------------------"
echo "Job Name: $JOB_NAME"
echo "Build Number: $BUILD_NUMBER"
echo "Workspace: $WORKSPACE"

echo ""
echo "=========================================="
echo "    HOST INFORMATION COLLECTION COMPLETE"
echo "=========================================="
Understanding the script:
  • echo displays headings and messages in the console.
  • hostname retrieves the machine hostname.
  • cat /etc/os-release displays Linux distribution details.
  • uname -r displays the kernel version.
  • nproc displays the number of available processing units.
  • free -h displays memory usage in human-readable format.
  • df -h displays filesystem disk usage.
  • hostname -I displays the machine's IP addresses.
  • whoami identifies the user executing the build.
  • uptime displays system uptime and load averages.

6. Save the Jenkins Job

Step 1 Scroll to the bottom of the configuration page.
Step 2 Click Save.
Step 3 Jenkins will redirect you to the linux-host-details job dashboard.
Job created successfully! Your first Jenkins Freestyle project is now configured.

7. Execute the Jenkins Job

Step 1 From the job dashboard, locate the left-side menu.
Step 2 Click Build Now.
Step 3 Look at the Build History section.
Step 4 Wait for the build to finish.
Step 5 Click the generated build number, such as #1.
Step 6 Click Console Output.

9. Understand the Build Result

At the end of the Console Output, Jenkins displays the build status.

Build Status Meaning
SUCCESS All shell commands completed successfully.
FAILURE A command failed or the build encountered an error.
UNSTABLE The build completed with configured checks or test failures.
ABORTED The build was stopped before completion.

10. Execute the Job Again

Step 1 Return to the linux-host-details job dashboard.
Step 2 Click Build Now again.
Step 3 Open the newly generated build number, such as #2.
Step 4 Click Console Output.

Jenkins executes the same script again and creates a new build record. Each execution receives a different build number.

12. Troubleshooting

Build fails immediately

Open Console Output and identify the command that failed. Check whether the required Linux command is available inside the Jenkins build executor.

Permission denied

Check which user is executing the Jenkins build and verify the required permissions.

Command not found

Some Linux commands may not be installed in the Jenkins container. Verify the availability of the command before using it.

Build remains in the queue

Check whether Jenkins has an available executor and whether the build is waiting for an agent.
