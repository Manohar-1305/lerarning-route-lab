Bash Scripting – Variables

Learn how to declare, assign, access, modify, and use variables in real-world Bash automation.

1. What Are Variables in Bash?

A variable is a named storage location used to hold a value that can be accessed and reused while a Bash script executes.

In DevOps, scripts frequently interact with servers, applications, containers, Kubernetes clusters, and cloud infrastructure. Instead of repeatedly writing the same values throughout a script, we store them in variables.

For example, consider a script that deploys an application:

#!/bin/bash

APP_NAME="payment-service"
ENVIRONMENT="production"
SERVER_IP="192.168.1.100"

echo "Deploying $APP_NAME"
echo "Environment: $ENVIRONMENT"
echo "Server: $SERVER_IP"

Here, APP_NAME, ENVIRONMENT, and SERVER_IP are variables. Their values can be reused anywhere in the script.

2. Declaring and Assigning Variables

In Bash, you do not need to specify a data type when creating a variable. You can assign a value directly using the assignment operator (=).

Syntax

VARIABLE_NAME="value"

Examples

#!/bin/bash

username="developer"
age=30
application="nginx"
server_ip="10.0.0.10"

echo "$username"
echo "$age"
echo "$application"
echo "$server_ip"

Important assignment rules

# Correct
name="Manohar"
port=8080

# Incorrect
name = "Manohar"
port = 8080

There must not be spaces around the assignment operator. Bash interprets spaces differently, so name = "Manohar" is not a valid variable assignment.

DevOps application: Store application names, server addresses, Docker image tags, Kubernetes namespaces, and deployment directories in variables instead of hardcoding them throughout your scripts.

3. Accessing Variables

To retrieve a variable's value, prefix its name with the dollar sign ($). 

#!/bin/bash

APP_NAME="learning-labs"
VERSION="2.5"
PORT=5000

echo "Application: $APP_NAME"
echo "Version: $VERSION"
echo "Port: $PORT"

Using curly braces

You can use curly braces to clearly identify where a variable name ends. This is especially useful when attaching additional text to a variable. 

#!/bin/bash

APP="nginx"

echo "${APP}_service"
echo "${APP}_deployment"

Output:

nginx_service
nginx_deployment

Without curly braces, Bash may interpret adjacent characters as part of the variable name.

4. Updating Variable Values

A variable's value can be changed during script execution. When you assign a new value, the previous value is replaced. 

#!/bin/bash

ENVIRONMENT="development"

echo "Initial environment: $ENVIRONMENT"

ENVIRONMENT="testing"

echo "Updated environment: $ENVIRONMENT"

ENVIRONMENT="production"

echo "Final environment: $ENVIRONMENT"

Output:

Initial environment: development
Updated environment: testing
Final environment: production

Appending values

You can append additional text to an existing variable using the += operator. 

#!/bin/bash

LOG_MESSAGE="Application started"

LOG_MESSAGE+=" successfully"

echo "$LOG_MESSAGE"

Output:

Application started successfully

5. Local Variables and Environment Variables

Bash variables can be local to a shell or function, or exported as environment variables so that child processes can access them.

Shell variable

#!/bin/bash

APP_ENV="production"

echo "$APP_ENV"

This variable is available in the current shell and script, but it is not automatically passed to child processes.

Environment variable using export

#!/bin/bash

export APP_ENV="production"
export APP_PORT=8080

bash -c 'echo "Environment: $APP_ENV"'
bash -c 'echo "Port: $APP_PORT"'

The export command makes the variables available to processes started by the current shell.

Difference

Shell Variable Environment Variable
Available in the current shell. Available in the current shell and its child processes.
Created using normal assignment. Created or promoted using export.
Not automatically inherited by child processes. Inherited by child processes.

6. Command Substitution in Variables

Sometimes you need to store the output of a Linux command in a variable. Bash provides command substitution using $(command).

Example: Store hostname

#!/bin/bash

SERVER_NAME=$(hostname)

echo "Server name: $SERVER_NAME"

Example: Store current date

#!/bin/bash

CURRENT_DATE=$(date +%Y-%m-%d)

echo "Current date: $CURRENT_DATE"

Example: Store disk usage

#!/bin/bash

DISK_USAGE=$(df -h / | awk 'NR==2 {print $5}')

echo "Root disk usage: $DISK_USAGE"

This is particularly useful in DevOps automation because scripts can dynamically collect system information instead of relying on manually entered values.

7. Special Bash Variables

Bash provides predefined variables that contain information about the script, its arguments, and its execution environment.

Variable Description
$0 Name or path used to execute the script.
$1 First command-line argument.
$2 Second command-line argument.
$# Number of positional arguments.
$@ All positional arguments.
$? Exit status of the previous command.
$$ Process ID of the current Bash shell.
$USER Current user's environment variable.
$HOME Current user's home directory.
$PWD Current working directory.

Example

#!/bin/bash

echo "Script name: $0"
echo "First argument: $1"
echo "Second argument: $2"
echo "Total arguments: $#"
echo "Current user: $USER"
echo "Home directory: $HOME"
echo "Working directory: $PWD"
echo "Shell PID: $$"

Execute:

bash variables.sh developer production

8. Variable Quoting and Expansion

Quoting determines how Bash interprets variable values. It is important when values contain spaces or special characters.

Double quotes

Double quotes allow variable expansion while preserving spaces within the value. 

#!/bin/bash

APP_NAME="Learning Labs"

echo "Deploying $APP_NAME"

Output:

Deploying Learning Labs

Single quotes

Single quotes preserve the literal text. Variables inside single quotes are not expanded. 

#!/bin/bash

APP_NAME="Learning Labs"

echo 'Deploying $APP_NAME'
echo "Deploying $APP_NAME"

Output:

Deploying $APP_NAME
Deploying Learning Labs
Important: Always quote variable expansions in commands when the value might contain spaces or wildcard characters. For example, use rm -rf "$DIRECTORY" rather than an unquoted variable.

9. Real-Time DevOps Example: Application Deployment Configuration

Consider a real deployment scenario. You have a Flask application called Learning Labs that needs to be deployed to a Linux server.

Instead of hardcoding application details throughout your deployment script, you define them as variables. If the application version, environment, or deployment directory changes, you only need to update the corresponding value.

deployment.sh

#!/bin/bash

# Application configuration
APP_NAME="learning-labs"
APP_VERSION="2.5.0"
ENVIRONMENT="production"

# Server configuration
SERVER_NAME=$(hostname)
SERVER_IP="192.168.1.100"
SSH_USER="ubuntu"

# Deployment configuration
DEPLOY_DIR="/opt/applications/$APP_NAME"
BACKUP_DIR="/opt/backups/$APP_NAME"

# Container configuration
DOCKER_IMAGE="$APP_NAME:$APP_VERSION"
CONTAINER_NAME="${APP_NAME}-container"
CONTAINER_PORT=5000

# Runtime information
DEPLOYMENT_DATE=$(date +%Y-%m-%d)
DEPLOYMENT_USER=$(whoami)

# Display deployment configuration
echo "================================"
echo "APPLICATION DEPLOYMENT DETAILS"
echo "================================"

echo "Application: $APP_NAME"
echo "Version: $APP_VERSION"
echo "Environment: $ENVIRONMENT"

echo "Server: $SERVER_NAME"
echo "Server IP: $SERVER_IP"
echo "SSH User: $SSH_USER"

echo "Deployment Directory: $DEPLOY_DIR"
echo "Backup Directory: $BACKUP_DIR"

echo "Docker Image: $DOCKER_IMAGE"
echo "Container Name: $CONTAINER_NAME"
echo "Container Port: $CONTAINER_PORT"

echo "Deployment Date: $DEPLOYMENT_DATE"
echo "Deployment User: $DEPLOYMENT_USER"

echo "================================"

Execute the script

nano deployment.sh

chmod +x deployment.sh

./deployment.sh

How variables are used in this example

Variable Purpose
APP_NAME Stores the application name.
APP_VERSION Stores the release version.
ENVIRONMENT Identifies the target environment.
SERVER_NAME Dynamically obtains the server hostname.
DEPLOY_DIR Stores the application deployment path.
DOCKER_IMAGE Combines the application name and version.
CONTAINER_NAME Builds the container name from the application name.
DEPLOYMENT_DATE Captures the current date.

Notice that DOCKER_IMAGE and CONTAINER_NAME use previously declared variables. This is an example of variable expansion and reuse in a practical automation script.

Real-world benefit: You can reuse the same deployment script for development, testing, and production by changing the configuration values. The example displays deployment configuration; it does not perform an actual SSH connection or Docker deployment.

Key Takeaways

  • Variables store reusable values in Bash scripts.
  • Use NAME="value" to assign a value.
  • Use $NAME or ${NAME} to access a variable.
  • Use export to pass variables to child processes.
  • Use $(command) to capture command output.
  • Special variables provide script arguments and execution information.
  • Use double quotes to preserve spaces while expanding variables.
  • Use variables to make DevOps automation configurable and reusable.
