Ansible APT Module

In this lab, you will learn how to use the Ansible APT module to manage software packages on Ubuntu servers. You will create playbooks to install, remove, update and upgrade packages. At the end, you will build a practical project that automates the installation of essential Linux administration tools.

1. What Is the APT Module?

APT stands for Advanced Package Tool. Ubuntu uses APT to install, update, upgrade and remove software packages.

For example, when you want to install a package such as curl, Ubuntu uses its package management system to download and install the required software.

Ansible provides the ansible.builtin.apt module to automate these package management operations across multiple Ubuntu servers.

Instead of manually installing packages on every server, you can define the required package configuration in a playbook and execute it against your inventory.

2. APT Module Syntax

The basic structure of the APT module looks like this: 

- name: Install a package
  ansible.builtin.apt:
    name: curl
    state: present

ansible.builtin.apt identifies the module, while name and state are parameters used to control the package.

3. Important APT Module Parameters

name

Specifies the package that you want Ansible to manage. You can specify a single package or multiple packages. 

name: curl

To manage multiple packages, use a YAML list:

name:
  - curl
  - wget
  - unzip

state

Specifies the desired state of the package. Ansible compares the current package state with the requested state and takes action when necessary.

  • present – Ensures the package is installed.
  • absent – Ensures the package is removed.
  • latest – Ensures the latest available package version is installed.

update_cache

Refreshes the local APT package information from configured repositories before performing package operations. 

update_cache: true

This is similar to refreshing package information before installing software. It does not itself upgrade installed packages.

cache_valid_time

Specifies how long the existing APT cache is considered valid, in seconds. 

cache_valid_time: 3600

In this example, Ansible refreshes the cache only when it is older than 3600 seconds (one hour).

upgrade

Upgrades installed packages using the available package information. 

upgrade: dist

The dist option performs a distribution-style package upgrade, allowing APT to handle dependency changes. It does not upgrade Ubuntu to another operating system release.

4. Install a Single Package

Create a playbook named install-package.yml. In this example, you will install the curl package. 

---
- name: Install Curl on Ubuntu
  hosts: all
  become: true

  tasks:
    - name: Install curl package
      ansible.builtin.apt:
        name: curl
        state: present
        update_cache: true

Understanding the Playbook

hosts: all targets all servers in the inventory.

become: true enables privilege escalation because installing software requires administrative permissions.

name: curl identifies the package to install.

state: present ensures that curl is installed. If it is already installed, Ansible leaves it unchanged.

update_cache: true refreshes package information before installing curl.

5. Install Multiple Packages

You do not need to create a separate task for every package. The APT module supports installing multiple packages in one task.

Create install-multiple-packages.yml. 

---
- name: Install Multiple Ubuntu Packages
  hosts: all
  become: true

  tasks:
    - name: Install administration tools
      ansible.builtin.apt:
        name:
          - curl
          - wget
          - unzip
          - tree
          - htop
        state: present
        update_cache: true
        cache_valid_time: 3600

The name parameter contains a list of five packages. Ansible ensures that all five packages are installed.

state: present applies to every package in the list.

6. Remove a Package

The APT module can also remove software packages. Create remove-package.yml. 

---
- name: Remove Package from Ubuntu
  hosts: all
  become: true

  tasks:
    - name: Remove curl package
      ansible.builtin.apt:
        name: curl
        state: absent

Understanding the Playbook

name: curl identifies the package to remove.

state: absent ensures that the package is not installed on the managed server.

If the package is already absent, Ansible does not need to remove it again.

7. Upgrade Installed Packages

You can use the APT module to upgrade installed packages. Create upgrade-packages.yml. 

---
- name: Upgrade Ubuntu Packages
  hosts: all
  become: true

  tasks:
    - name: Refresh APT package cache
      ansible.builtin.apt:
        update_cache: true
        cache_valid_time: 3600

    - name: Upgrade installed packages
      ansible.builtin.apt:
        upgrade: dist

Understanding the Playbook

The first task refreshes the package information so that APT can identify available updates.

The second task upgrades installed packages using the distribution-style upgrade operation.

Important: Package upgrades can change software versions and dependencies. Test updates before applying them to production servers.

8. Idempotency in the APT Module

Idempotency is an important concept in Ansible. It means that running the same playbook multiple times should not repeatedly change a system that is already in the desired state.

Consider this task:

- name: Ensure curl is installed
  ansible.builtin.apt:
    name: curl
    state: present

When curl is not installed, Ansible installs it. When curl is already installed, Ansible leaves it unchanged.

If you execute the playbook again without any changes needed, the task should report ok instead of changed.

9. Practical Project: Ubuntu Administration Tools Setup

In this project, you will automate the installation of essential Linux administration tools on Ubuntu servers using the APT module.

You will create one inventory file and one Ansible playbook. The playbook will refresh the package cache and ensure that all required packages are installed.

Project Requirements

  • Target all servers in the inventory.
  • Refresh the APT package cache.
  • Install curl for HTTP requests.
  • Install wget for downloading files.
  • Install unzip for extracting ZIP archives.
  • Install tree for viewing directory structures.
  • Install htop for interactive process monitoring.
  • Ensure all packages remain installed when the playbook runs again.

Step 1: Create the Project Directory

mkdir -p ubuntu-admin-setup
cd ubuntu-admin-setup

Step 2: Create the Inventory File

Create a file named inventory.ini. 

[ubuntu_servers]
192.168.1.101 ansible_user=ubuntu
192.168.1.102 ansible_user=ubuntu

Replace the example IP addresses and username with the connection details of your managed Ubuntu servers.

Step 3: Create the Playbook

Create a file named ubuntu-admin-setup.yml. 

---
- name: Configure Ubuntu Administration Tools
  hosts: all
  become: true

  tasks:

    - name: Refresh APT package cache
      ansible.builtin.apt:
        update_cache: true
        cache_valid_time: 3600

    - name: Install required administration tools
      ansible.builtin.apt:
        name:
          - curl
          - wget
          - unzip
          - tree
          - htop
        state: present

Step 4: Understand the Project Playbook

The playbook contains two tasks.

The first task refreshes the APT package cache. The cache_valid_time parameter avoids unnecessary cache refreshes when the existing cache is less than one hour old.

The second task installs five administration tools using a single APT module task.

The state: present parameter ensures that all five packages are installed. If a package is already present, Ansible does not reinstall it.

Step 5: Validate the Playbook

Check the YAML syntax and playbook structure before execution. 

ansible-playbook -i inventory.ini ubuntu-admin-setup.yml --syntax-check

If the playbook is valid, Ansible displays a syntax OK message.

Step 6: Execute the Playbook

ansible-playbook -i inventory.ini ubuntu-admin-setup.yml

Ansible connects to the inventory hosts, refreshes the APT cache when required and installs the five administration packages.

Step 7: Execute the Playbook Again

Run the same playbook again:

ansible-playbook -i inventory.ini ubuntu-admin-setup.yml

Since the packages are already installed, the package installation task should report ok instead of changed, provided the desired package state has not changed.

Project completed: You have automated Ubuntu package management using an Ansible playbook and the APT module.

Why Do We Use the Ansible APT Module?

Ubuntu uses APT (Advanced Package Tool) to manage software packages. Whenever you install, update, upgrade or remove software on an Ubuntu server, APT handles the package management operations.

In a real-world environment, administrators may manage dozens or hundreds of Ubuntu servers. Installing or updating software manually on every server takes time and increases the possibility of configuration differences and human errors.

The Ansible APT module solves this problem by allowing administrators to define package requirements in a playbook and apply them consistently across multiple Ubuntu servers.

1. Centralized Package Management

Instead of connecting to every server and installing packages individually, you can define all required packages in one Ansible playbook. Ansible applies the same package configuration to every server in the selected inventory group.

For example, if your organization requires curl, wget, unzip and htop on all Ubuntu servers, you can define these packages in one task. Ansible ensures that the required packages are installed across the managed servers.

2. Consistent Server Configuration

Inconsistent software installations can cause problems. One server might have curl installed while another server does not. Different package versions can also lead to unexpected application behavior.

By using the APT module, you can define the desired package state and apply it consistently across your servers. This helps maintain a standardized server configuration.

3. Idempotency and Reduced Manual Work

The APT module supports idempotent operations. This means Ansible checks the existing package state before making changes.

For example, when you specify state: present, Ansible checks whether the requested package is installed. If it is already installed, Ansible does not install it again. If it is missing, Ansible installs it.

This allows you to execute the same playbook repeatedly without unnecessarily reinstalling packages.

4. Automated Software Updates

Servers need regular software updates to receive security fixes, bug fixes and package improvements. Manually updating multiple servers can become difficult as the infrastructure grows.

The APT module allows you to automate package cache updates and package upgrades through Ansible playbooks. You can execute the same patching workflow across your managed Ubuntu servers.

5. Package Installation and Removal

The APT module supports different package states. You can install required software using state: present, remove unwanted software using state: absent, and install the latest available package version using state: latest.

This makes the APT module useful throughout the server lifecycle, from initial configuration to ongoing software maintenance.

6. Real-World Example

Imagine an organization managing 50 Ubuntu servers. Every server requires the following packages:

  • curl for making HTTP requests.
  • wget for downloading files.
  • unzip for extracting ZIP archives.
  • htop for monitoring running processes.
  • tree for viewing directory structures.

Without automation, an administrator would need to install these packages individually on all 50 servers.

With Ansible, the administrator creates one playbook containing the required package list and executes it against the inventory. Ansible handles the installation across all selected servers.

7. Why Is This Important for a DevOps Engineer?

Package management is a fundamental server administration activity. DevOps engineers frequently need to install dependencies, maintain software versions, apply security updates and prepare servers for application deployments.

Understanding the APT module helps you automate these repetitive activities, maintain consistent environments and reduce manual intervention across Ubuntu infrastructure.
