Ansible File Module

The Ansible File module manages files, directories, symbolic links, permissions and ownership on managed hosts. It can create, delete and modify filesystem objects without manually executing Linux commands.

1. What Is the File Module?

The ansible.builtin.file module manages filesystem objects on remote managed hosts.

Common use cases include:

  • Creating files and directories.
  • Deleting files and directories.
  • Changing file permissions.
  • Changing file ownership and group.
  • Creating symbolic links.
  • Changing timestamps.
  • Managing directory structures.

2. How Does the File Module Work?

             Ansible Controller
             ------------------
             Playbook
                 |
                 |
             SSH Connection
                 |
                 v
             Managed Host
             -------------
             Filesystem
                 |
                 v
          Create / Delete / Modify
                 |
                 v
          Updated File or Directory

Ansible connects to the managed host and applies the requested filesystem changes.

3. Important Parameters

Parameter Description
path Path of the file or directory to manage.
state Defines whether to create, remove or manage the filesystem object.
owner Sets the file or directory owner.
group Sets the file or directory group.
mode Sets filesystem permissions.
recurse Applies ownership and permission changes recursively to directory contents.
src Source path for symbolic links.
follow Controls whether to follow symbolic links when managing attributes.
force Controls whether an existing destination is replaced when creating a symbolic link.
access_time Sets the last access timestamp.
modification_time Sets the last modification timestamp.

4. Understanding the State Parameter

The state parameter determines what Ansible should do with the filesystem object.

State Purpose
directory Creates a directory if it does not exist.
touch Creates an empty file if missing and updates its timestamps.
file Manages attributes of an existing file or symbolic link; does not create a missing regular file.
absent Removes the specified file, directory or symbolic link.
link Creates a symbolic link.
hard Creates a hard link.

5. Create a Directory

Use state: directory to create a directory on the managed host.

Playbook: create-directory.yml

---
- name: Create directory
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directory
      ansible.builtin.file:
        path: /tmp/learning-labs
        state: directory
        mode: '0755'

If the directory already exists, Ansible ensures that its requested attributes are applied.

6. Create an Empty File

Use state: touch to create an empty file when it does not exist.

Playbook: create-file.yml

---
- name: Create empty file
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application log file
      ansible.builtin.file:
        path: /tmp/learning-labs/application.log
        state: touch
        owner: root
        group: root
        mode: '0644'
Important: The touch state updates the access and modification timestamps when the task runs. It is not necessarily a no-change operation on repeated playbook executions.

7. Change File Permissions

Use the mode parameter to change file permissions. The file must already exist.

Playbook: file-permissions.yml

---
- name: Change file permissions
  hosts: ansible-client
  become: true

  tasks:
    - name: Set application log permissions
      ansible.builtin.file:
        path: /tmp/learning-labs/application.log
        state: file
        mode: '0640'

The permission 0640 means:

  • Owner: Read and write.
  • Group: Read only.
  • Others: No permissions.

8. Change File Ownership

9. Create Nested Directories

The File module can create a complete directory path even when its parent directories do not exist.

Playbook: nested-directories.yml

---
- name: Create nested directories
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directory structure
      ansible.builtin.file:
        path: /tmp/learning-labs/config/production
        state: directory
        owner: root
        group: root
        mode: '0755'

10. Apply Permissions Recursively

The recurse parameter applies ownership and permission changes to the directory and its contents.

Playbook: recursive-permissions.yml

---
- name: Apply recursive permissions
  hosts: ansible-client
  become: true

  tasks:
    - name: Set ownership and permissions recursively
      ansible.builtin.file:
        path: /tmp/learning-labs
        state: directory
        owner: root
        group: root
        mode: '0755'
        recurse: true
Important: Recursive permission changes can affect every file and directory under the specified path. Use this carefully on production systems.

13. Create a Symbolic Link

A symbolic link points to another file or directory. Use state: link and specify the target using src.

Playbook: symbolic-link.yml

---
- name: Create symbolic link
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application log directory
      ansible.builtin.file:
        path: /tmp/application-logs
        state: directory
        mode: '0755'

    - name: Create symbolic link
      ansible.builtin.file:
        src: /tmp/application-logs
        path: /tmp/logs-link
        state: link

The link /tmp/logs-link points to /tmp/application-logs.

14. Create a Hard Link

A hard link creates another directory entry that references the same underlying file data. The source file must already exist, and both paths must be on the same filesystem.

Playbook: hard-link.yml

---
- name: Create hard link
  hosts: ansible-client
  become: true

  tasks:
    - name: Create original file
      ansible.builtin.copy:
        content: "Learning Ansible hard links\n"
        dest: /tmp/original-file.txt
        mode: '0644'

    - name: Create hard link
      ansible.builtin.file:
        src: /tmp/original-file.txt
        path: /tmp/hard-link.txt
        state: hard

15. Practical Project: Manage Application Filesystem

Project Objective

Build an Ansible playbook that prepares a complete application directory structure and manages its files, permissions and links.

Requirements:
  1. Create an application directory.
  2. Create configuration, logs and backup directories.
  3. Create an empty application log file.
  4. Set the correct ownership and permissions.
  5. Create a symbolic link to the logs directory.
  6. Apply recursive permissions to the backup directory.
Project playbook: manage-application-filesystem.yml 
---
- name: Manage application filesystem
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directory
      ansible.builtin.file:
        path: /tmp/learning-labs
        state: directory
        owner: root
        group: root
        mode: '0755'

    - name: Create application subdirectories
      ansible.builtin.file:
        path: "{{ item }}"
        state: directory
        owner: root
        group: root
        mode: '0755'
      loop:
        - /tmp/learning-labs/config
        - /tmp/learning-labs/logs
        - /tmp/learning-labs/backups

    - name: Create application log file
      ansible.builtin.file:
        path: /tmp/learning-labs/logs/application.log
        state: touch
        owner: root
        group: root
        mode: '0644'

    - name: Apply backup directory permissions
      ansible.builtin.file:
        path: /tmp/learning-labs/backups
        state: directory
        owner: root
        group: root
        mode: '0750'
        recurse: true

    - name: Create logs symbolic link
      ansible.builtin.file:
        src: /tmp/learning-labs/logs
        path: /tmp/application-logs
        state: link

Why Do We Use the Ansible File Module?

In production environments, applications require specific directory structures, file permissions and ownership settings to operate correctly.

For example, an application may require separate directories for configuration files, application logs, backups and temporary data. These directories must be created consistently across development, testing and production servers.

The Ansible File module automates filesystem management across multiple managed hosts. It helps administrators maintain consistent permissions, ownership and directory structures without manually executing Linux commands on every server.

It is commonly used in server provisioning, application deployment, configuration management and DevOps automation.
