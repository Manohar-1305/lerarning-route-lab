Ansible Command Module

Learn how to execute Linux commands on managed hosts using Ansible.

1. What Is the Command Module?

The ansible.builtin.command module executes commands on managed hosts without using a shell.

It is useful for simple commands such as checking the hostname, uptime and directory contents.

2. Execute a Command

Check how long the managed host has been running:

ansible ansible-client -m ansible.builtin.command -a 'uptime'

Here, -m specifies the module and -a provides the command to execute.

3. Check the Hostname

Find the hostname of the managed host:

ansible ansible-client -m ansible.builtin.command -a 'hostname'

This helps verify which host Ansible is managing.

4. List Directory Contents

List files and directories inside /tmp:

ansible ansible-client -m ansible.builtin.command -a 'ls -la /tmp'

The command module executes the command directly. It does not process shell features such as pipes, redirection or wildcard expansion.

5. Create Your First Playbook

Create a playbook on the Ansible controller:

vi command-playbook.yml

Press i and add:

---
- name: Command module example
  hosts: ansible-client

  tasks:
    - name: Check hostname
      ansible.builtin.command:
        cmd: hostname
      register: hostname_output
      changed_when: false

    - name: Display hostname
      ansible.builtin.debug:
        var: hostname_output.stdout

The command task executes hostname. The register keyword saves its result, and the debug task displays the hostname.

Save the file:

Esc
:wq

6. Execute the Playbook

Run the playbook:

ansible-playbook command-playbook.yml

Ansible executes the command on ansible-client and displays the hostname.

7. Use the chdir Parameter

The chdir parameter changes the working directory before executing a command.

Add this task under the existing tasks section:

    - name: List files in /tmp
      ansible.builtin.command:
        cmd: ls -la
        chdir: /tmp
      changed_when: false

Execute the playbook again:

ansible-playbook command-playbook.yml

8. Use the creates Parameter

The creates parameter skips a command when the specified file already exists.

Add this task to your playbook:

    - name: Create a marker file
      ansible.builtin.command:
        cmd: touch /tmp/ansible-marker
        creates: /tmp/ansible-marker

Run the playbook:

ansible-playbook command-playbook.yml

The first run creates the file. Subsequent runs skip the command because the file already exists.

9. Validate Your Playbook

Check the playbook for syntax errors:

ansible-playbook --syntax-check command-playbook.yml

Execute it:

ansible-playbook command-playbook.yml

10. Real-Time Project: Managed Host Health Report

Project objective

Create an Ansible playbook that collects basic system information from a managed host and displays a health report.

Step 1: Create the project playbook

vi health-report.yml

Press i and add the following:

---
- name: Managed Host Health Report
  hosts: ansible-client

  tasks:
    - name: Collect hostname
      ansible.builtin.command:
        cmd: hostname
      register: host_name
      changed_when: false

    - name: Collect system uptime
      ansible.builtin.command:
        cmd: uptime
      register: system_uptime
      changed_when: false

    - name: Check disk usage
      ansible.builtin.command:
        cmd: df -h /
      register: disk_usage
      changed_when: false

    - name: Check memory usage
      ansible.builtin.command:
        cmd: free -h
      register: memory_usage
      changed_when: false

    - name: Display health report
      ansible.builtin.debug:
        msg:
          - "Hostname: {{ host_name.stdout }}"
          - "Uptime: {{ system_uptime.stdout }}"
          - "Disk Usage:"
          - "{{ disk_usage.stdout }}"
          - "Memory Usage:"
          - "{{ memory_usage.stdout }}"

Save the file:

Esc
:wq

Step 2: Validate the playbook

ansible-playbook --syntax-check health-report.yml

Step 3: Execute the project

ansible-playbook health-report.yml

Step 4: Review the report

The output displays:

  • Managed host hostname.
  • System uptime.
  • Root filesystem disk usage.
  • Memory usage.

You can run this playbook whenever you need a quick health report from the managed host.
