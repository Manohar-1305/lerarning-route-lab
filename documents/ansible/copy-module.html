Ansible Copy Module

The Ansible Copy module transfers files from the Ansible controller to managed hosts. It can also create files directly on managed hosts using the content parameter.

1. What Is the Copy Module?

The ansible.builtin.copy module is used to copy files from the controller machine to remote managed hosts.

Common use cases include:

  • Copying application configuration files.
  • Deploying scripts to remote servers.
  • Copying certificates and other required files.
  • Creating configuration files with specified content.
  • Setting file permissions and ownership during deployment.

2. How Does the Copy Module Work?

                  Ansible Controller
                  ------------------
                  Source file
                  /project/files/app.conf
                         |
                         |
                    Ansible SSH
                         |
                         v
                  Managed Host
                  -------------
                  /tmp/app.conf

The source file is read from the Ansible controller and transferred to the managed host. The destination path specifies where the file should be placed on the managed host.

3. Important Parameters

Parameter Description
src Source file path on the Ansible controller.
dest Destination path on the managed host.
content Creates a file using the supplied text content.
owner Sets the file owner.
group Sets the file group.
mode Sets file permissions.
backup Creates a backup before replacing an existing file.
force Controls whether an existing destination file is replaced.
remote_src Indicates that the source file is already on the managed host.
directory_mode Sets permissions for newly created destination directories.
validate Runs a validation command before replacing the destination file.

4. Copy a File to a Managed Host

In this example, we copy an application configuration file from the controller to the managed host.

Project structure on the controller:

ansible-project/
├── files/
│   └── app.conf
└── copy-file.yml

Source file: files/app.conf

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=development

Playbook: copy-file.yml

---
- name: Copy configuration file
  hosts: ansible-client
  become: true

  tasks:
    - name: Copy application configuration
      ansible.builtin.copy:
        src: files/app.conf
        dest: /tmp/app.conf
        owner: root
        group: root
        mode: '0644'

The source path is relative to the playbook project. The destination path is on the managed host.

5. Create a File Using the Content Parameter

You do not always need a separate source file. The content parameter creates a file directly on the managed host.

Playbook: create-file.yml

---
- name: Create application configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application configuration file
      ansible.builtin.copy:
        content: |
          APP_NAME=learning-labs
          APP_PORT=8080
          APP_ENV=production
        dest: /tmp/application.conf
        owner: root
        group: root
        mode: '0644'

6. Set File Permissions

The Copy module can set ownership and permissions while copying a file.

Playbook: copy-permissions.yml

---
- name: Copy file with specific permissions
  hosts: ansible-client
  become: true

  tasks:
    - name: Create a protected configuration file
      ansible.builtin.copy:
        content: |
          DATABASE_HOST=127.0.0.1
          DATABASE_PORT=3306
        dest: /tmp/database.conf
        owner: root
        group: root
        mode: '0600'
Important: Use quoted permission values such as '0644' and '0600'. This avoids YAML interpreting them as ordinary numbers.

7. Create a Backup Before Replacing a File

When a destination file already exists, the backup parameter can preserve its previous version before Ansible replaces it.

Playbook: copy-backup.yml

---
- name: Copy file with backup
  hosts: ansible-client
  become: true

  tasks:
    - name: Update application configuration
      ansible.builtin.copy:
        content: |
          APP_NAME=learning-labs
          APP_PORT=9090
          APP_ENV=production
        dest: /tmp/application.conf
        backup: true
        mode: '0644'

8. Copy a File from One Remote Location to Another

The remote_src parameter tells Ansible that the source file is already present on the managed host.

Playbook: remote-copy.yml

---
- name: Copy file within managed host
  hosts: ansible-client
  become: true

  tasks:
    - name: Copy existing remote file
      ansible.builtin.copy:
        src: /tmp/application.conf
        dest: /tmp/application-backup.conf
        remote_src: true
        mode: '0644'

9. Practical Project: Deploy Application Configuration

Project Objective

Deploy configuration files for an application on the managed host using the Ansible Copy module.

Requirements:
  1. Create an application configuration file.
  2. Deploy the configuration to ansible-client.
  3. Set the owner and group to root.
  4. Set permissions to 0644.
  5. Create a separate environment configuration file using the content parameter.
  6. Deploy an updated configuration with backup enabled.
Project playbook: deploy-application.yml 
---
- name: Deploy application configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Deploy application configuration
      ansible.builtin.copy:
        content: |
          APP_NAME=learning-labs
          APP_PORT=8080
          APP_ENV=production
        dest: /tmp/learning-labs.conf
        owner: root
        group: root
        mode: '0644'

    - name: Create environment configuration
      ansible.builtin.copy:
        content: |
          ENVIRONMENT=production
          LOG_LEVEL=INFO
          DEBUG=false
        dest: /tmp/learning-labs.env
        owner: root
        group: root
        mode: '0644'

    - name: Update configuration with backup
      ansible.builtin.copy:
        content: |
          APP_NAME=learning-labs
          APP_PORT=9090
          APP_ENV=production
        dest: /tmp/learning-labs.conf
        backup: true
        owner: root
        group: root
        mode: '0644'

Why Do We Use the Ansible Copy Module?

In real-world infrastructure, administrators frequently need to deploy configuration files, scripts, certificates and application settings across multiple servers.

Without automation, administrators would need to connect to each server individually and transfer files manually. This becomes time-consuming and difficult to maintain as the infrastructure grows.

The Ansible Copy module automates this process. A single playbook can distribute the same configuration to multiple managed hosts, maintain consistent file permissions and create backups before replacing existing files.

It is commonly used in application deployment, server configuration, infrastructure automation and configuration management.
