Ansible until Keyword

The until keyword allows Ansible to retry a task repeatedly until a specified condition becomes true. It is useful when an operation may not succeed immediately, such as waiting for an application endpoint or service to become available.

1. Why Do We Need until?

Consider a deployment scenario where you start an application. The application process may start immediately, but its API endpoint may take several seconds to become available.

If you check the endpoint only once, the task may fail because the application is still initializing.

Instead of checking manually or writing repeated tasks, you can use until. Ansible repeats the task until the condition is satisfied or the retry limit is reached.

2. Basic Syntax

- name: Wait until condition is satisfied
  ansible.builtin.command:
    cmd: your-command
  register: result
  until: result.rc == 0
  retries: 5
  delay: 3

The main options are:

Keyword Purpose
until Condition that must become true.
retries Maximum number of attempts after the initial attempt.
delay Seconds to wait between attempts.
register Stores the result of the latest attempt.
Important: Ansible performs the initial attempt and then retries according to the configured retry limit. For example, retries: 5 allows up to six total attempts.

3. Example: Retry Until a Command Succeeds

The following example checks whether a file exists. If the file is not present, the command returns a non-zero exit code and Ansible retries the task. 

---
- name: Wait for a file
  hosts: ansible-client
  become: true

  tasks:
    - name: Check whether application file exists
      ansible.builtin.command:
        cmd: test -f /tmp/application.ready
      register: file_check
      changed_when: false
      until: file_check.rc == 0
      retries: 5
      delay: 3

    - name: Display success message
      ansible.builtin.debug:
        msg: "Application ready file detected"

Ansible checks the file, waits three seconds between unsuccessful attempts, and retries until the file exists or the retry limit is reached.

4. Example: Wait for an HTTP Endpoint

A common DevOps use case is waiting for an application API to respond. You can use the URI module to check an HTTP endpoint. 

---
- name: Wait for application API
  hosts: ansible-client
  become: true

  tasks:
    - name: Check application health endpoint
      ansible.builtin.uri:
        url: http://127.0.0.1:8080/health
        method: GET
        status_code: 200
      register: api_response
      until: api_response.status == 200
      retries: 10
      delay: 5

This task checks the health endpoint repeatedly. It completes when the endpoint returns HTTP status code 200.

If the endpoint does not return the expected status within the configured attempts, the task fails.

Note: This example assumes an application is listening on port 8080 on the target container. The endpoint must exist for the check to succeed.

5. Example: Retry Until Command Output Matches

You can also use command output as the condition. 

---
- name: Wait for expected application output
  hosts: ansible-client
  become: true

  tasks:
    - name: Check application status
      ansible.builtin.command:
        cmd: /usr/bin/printf "STARTING"
      register: app_status
      changed_when: false
      until: "'RUNNING' in app_status.stdout"
      retries: 5
      delay: 2

The command always returns STARTING, so the condition never becomes true. Ansible retries and eventually marks the task as failed after exhausting its attempts.

This demonstrates how the output of a task can control retry behavior.

6. Understanding Retry Execution

Consider this configuration: 

retries: 4
delay: 5
until: result.rc == 0

The execution behaves as follows:

Attempt Result Action
1 Failure Wait 5 seconds and retry
2 Failure Wait 5 seconds and retry
3 Failure Wait 5 seconds and retry
4 Failure Wait 5 seconds and retry
5 Success Stop retrying

The table illustrates a successful fifth attempt. If all five attempts fail, the task is marked as failed.

7. Difference Between loop and until

Keyword Purpose
loop Executes a task for each item in a list.
until Repeats a task until a condition becomes true.

Example using loop: 

- name: Display application names
  ansible.builtin.debug:
    msg: "{{ item }}"
  loop:
    - frontend
    - backend
    - database

Example using until: 

- name: Wait for application
  ansible.builtin.command:
    cmd: test -f /tmp/application.ready
  register: result
  changed_when: false
  until: result.rc == 0
  retries: 5
  delay: 3

A loop processes multiple values. An until condition repeats an operation until its result satisfies a condition.

8. Practical Lab: Wait for an Application Ready File

Scenario

You are deploying an application. Another process will create a readiness file at /tmp/application.ready. Your playbook must wait until that file exists.

Create this playbook:

---
- name: Application readiness check
  hosts: ansible-client
  become: true

  tasks:
    - name: Wait until readiness file exists
      ansible.builtin.command:
        cmd: test -f /tmp/application.ready
      register: readiness_result
      changed_when: false
      until: readiness_result.rc == 0
      retries: 10
      delay: 3

    - name: Display readiness confirmation
      ansible.builtin.debug:
        msg: "Application is ready"

    - name: Verify readiness file
      ansible.builtin.command:
        cmd: cat /tmp/application.ready
      changed_when: false

Run from ansible-controller:

ansible-playbook application-readiness.yml

Prepare the lab:

Before running the playbook, create the readiness file on ansible-client through a separate test process or another playbook. For example, the file can contain: 

Application is ready

Expected behavior:

  • Ansible checks whether the readiness file exists.
  • If absent, Ansible waits three seconds before retrying.
  • When the file exists, the condition becomes true.
  • The readiness confirmation task executes.
  • The file content is displayed.

9. Important Points About until

  • until requires a condition that evaluates to true or false.
  • register is commonly used to capture the task result.
  • retries controls the retry limit.
  • delay controls the wait between attempts.
  • Ansible stops retrying when the condition becomes true.
  • If the condition never becomes true, the task eventually fails.
  • The registered result contains the result of the final attempt.

Why Do We Use the Ansible until Keyword?

In real DevOps environments, applications and infrastructure components do not always become ready immediately. A service may need time to initialize, an API may take several seconds to respond, or a deployment process may create a readiness file only after completing its work.

If automation checks these resources only once, it may report a failure even though the resource would become available shortly.

The until keyword solves this problem by allowing Ansible to retry a task until a defined condition becomes true. You can configure the maximum number of attempts and the delay between them.

This is particularly useful for application health checks, deployment readiness validation, service availability checks, and infrastructure initialization.

It makes automation more reliable by accounting for operations that require time to complete instead of assuming that every resource is immediately available.
