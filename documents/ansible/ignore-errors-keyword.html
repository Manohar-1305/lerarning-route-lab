Ansible ignore_errors Keyword

The ignore_errors keyword allows an Ansible playbook to continue executing subsequent tasks when a task fails.

1. What Is ignore_errors?

Normally, when a task fails, Ansible stops executing subsequent tasks on that host in the current play.

When you use ignore_errors: true, Ansible records the task as failed but continues with the next task. 

- name: Run a task that may fail
  ansible.builtin.command:
    cmd: /bin/false
  ignore_errors: true

The command /bin/false returns a non-zero exit code. Ansible marks the task as failed, but does not stop the play because the error is being ignored for execution flow.

2. Basic Syntax

---
- name: Demonstrate ignore_errors
  hosts: ansible-client
  become: true

  tasks:
    - name: Task that may fail
      ansible.builtin.command:
        cmd: /bin/false
      ignore_errors: true

    - name: Continue after failure
      ansible.builtin.debug:
        msg: "This task executes after the failed task"

The first task fails, but the second task still executes.

3. Understanding Task Execution

Task Result
Task 1: Command returns non-zero Failed
ignore_errors: true Failure is allowed to continue
Task 2: Debug message Executed
Important: ignore_errors does not convert a failed task into a successful task. The task remains failed in the playbook output.

4. Example: Optional File Check

Imagine that your automation checks for an optional configuration file. If the file does not exist, you still want the remaining tasks to run. 

---
- name: Check optional configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Check optional configuration file
      ansible.builtin.command:
        cmd: test -f /tmp/application.conf
      register: config_check
      changed_when: false
      ignore_errors: true

    - name: Display next task message
      ansible.builtin.debug:
        msg: "Continuing with application configuration"

    - name: Create application directory
      ansible.builtin.file:
        path: /tmp/application
        state: directory
        mode: '0755'

If /tmp/application.conf does not exist:

  • The file check returns a non-zero exit code.
  • Ansible marks the check task as failed.
  • The debug task still executes.
  • The application directory is created.

5. Example: Multiple Tasks After a Failure

You can use ignore_errors on an individual task and continue with several subsequent tasks. 

---
- name: Continue after an optional operation
  hosts: ansible-client
  become: true

  tasks:
    - name: Run optional operation
      ansible.builtin.command:
        cmd: /bin/false
      ignore_errors: true

    - name: Check hostname
      ansible.builtin.command:
        cmd: hostname
      register: host_result
      changed_when: false

    - name: Display hostname
      ansible.builtin.debug:
        var: host_result.stdout

    - name: Display completion message
      ansible.builtin.debug:
        msg: "Remaining tasks completed"

The optional operation fails, but the remaining tasks execute.

6. Difference Between ignore_errors and failed_when

Keyword Purpose
ignore_errors Allows execution to continue after a task failure.
failed_when Defines the condition that determines whether a task is failed.

Example using ignore_errors: 

- name: Run command
  ansible.builtin.command:
    cmd: /bin/false
  ignore_errors: true

Example using failed_when: 

- name: Run command
  ansible.builtin.command:
    cmd: /bin/false
  register: command_result
  changed_when: false
  failed_when: command_result.rc == 0

In the second example, the task is not marked as failed because the condition evaluates to false, even though the command returns a non-zero exit code.

Important: Use ignore_errors only when continuing after a failure is intentional. Otherwise, it can hide problems that should stop your automation.

7. Practical Lab: Continue Deployment After an Optional Check

Scenario

You are preparing an application deployment. An optional configuration file may or may not exist. The deployment directory must still be created even if the file check fails.

Create this playbook:

---
- name: Optional configuration validation
  hosts: ansible-client
  become: true

  tasks:
    - name: Check optional configuration
      ansible.builtin.command:
        cmd: test -f /tmp/optional-app.conf
      register: config_result
      changed_when: false
      ignore_errors: true

    - name: Display configuration check result
      ansible.builtin.debug:
        msg: "Configuration check return code: {{ config_result.rc }}"

    - name: Create deployment directory
      ansible.builtin.file:
        path: /tmp/ansible-deployment
        state: directory
        mode: '0755'

    - name: Confirm deployment directory
      ansible.builtin.command:
        cmd: test -d /tmp/ansible-deployment
      changed_when: false

    - name: Display completion
      ansible.builtin.debug:
        msg: "Deployment preparation completed"

Run from ansible-controller:

ansible-playbook optional-config.yml

Expected behavior:

  • The optional file check may fail if the file is absent.
  • Ansible continues to the next task.
  • The deployment directory is created.
  • The directory verification executes.
  • The completion message is displayed.

Why Do We Use the Ansible ignore_errors Keyword?

In real DevOps environments, not every operation is mandatory. Some checks are optional, and some tasks may fail without preventing the remaining automation from completing its intended work.

For example, a deployment playbook might check for an optional configuration file, attempt to remove an old temporary file, or perform a non-critical validation. A failure in such an operation may not need to stop the entire deployment.

The ignore_errors keyword allows Ansible to continue executing subsequent tasks while retaining the failed status of the original task.

This gives you control over execution flow. However, critical failures such as application deployment errors, permission problems, or infrastructure failures should not be ignored without a clear reason.
