Ansible include_tasks Module

The include_tasks module allows you to include tasks from another YAML file inside your playbook. Instead of writing every task in one large playbook, you can separate tasks into smaller reusable files.

1. Why Do We Need include_tasks?

Consider a playbook that performs several operations on an Ubuntu server:

  • Create directories.
  • Create users.
  • Install packages.
  • Create configuration files.
  • Set file permissions.

If all these tasks are written in one playbook, the file can become difficult to maintain.

We can divide the tasks into separate files and include them in the main playbook whenever required.

2. Basic Syntax

---
- name: Main playbook
  hosts: ansible-client
  become: true

  tasks:
    - name: Include additional tasks
      ansible.builtin.include_tasks: tasks.yml

In this example, Ansible loads and executes the tasks defined in tasks.yml.

3. Understanding the Syntax

Component Purpose
include_tasks Includes tasks from another YAML file.
tasks.yml The file containing the additional tasks.
ansible.builtin The built-in Ansible collection containing the module.
tasks The main playbook section where tasks are defined.
Important: The included task file contains a list of tasks. It does not need its own hosts, become, or tasks sections.

4. Create a Separate Task File

First, create a file named setup_tasks.yml in the same directory as your main playbook.

setup_tasks.yml

---
- name: Create application directory
  ansible.builtin.file:
    path: /opt/myapp
    state: directory
    mode: '0755'

- name: Create log directory
  ansible.builtin.file:
    path: /opt/myapp/logs
    state: directory
    mode: '0755'

- name: Create application information file
  ansible.builtin.copy:
    dest: /opt/myapp/info.txt
    content: "Application configured using Ansible\n"
    mode: '0644'

This file contains three tasks. It does not contain a play definition.

5. Include the Task File in the Main Playbook

Create another file named main.yml.

main.yml

---
- name: Configure application directories
  hosts: ansible-client
  become: true

  tasks:
    - name: Run application setup tasks
      ansible.builtin.include_tasks: setup_tasks.yml

When the main playbook runs, Ansible includes and executes all three tasks from setup_tasks.yml on the target host.

6. Execute the Playbook

Run the playbook from your Ansible controller:

ansible-playbook main.yml

To check the result, create another playbook named verify.yml.

---
- name: Verify application setup
  hosts: ansible-client
  become: true

  tasks:
    - name: Check application directory
      ansible.builtin.command: test -d /opt/myapp
      changed_when: false

    - name: Check log directory
      ansible.builtin.command: test -d /opt/myapp/logs
      changed_when: false

    - name: Read application information
      ansible.builtin.command: cat /opt/myapp/info.txt
      register: app_info
      changed_when: false

    - name: Display application information
      ansible.builtin.debug:
        var: app_info.stdout

Execute the verification playbook:

ansible-playbook verify.yml

7. Include Multiple Task Files

You can include multiple task files in the same playbook. Each file can represent a separate configuration area.

Example directory structure:

ansible-project/
├── main.yml
├── users.yml
├── directories.yml
└── packages.yml

main.yml

---
- name: Configure Ubuntu server
  hosts: ansible-client
  become: true

  tasks:
    - name: Configure users
      ansible.builtin.include_tasks: users.yml

    - name: Configure directories
      ansible.builtin.include_tasks: directories.yml

    - name: Install packages
      ansible.builtin.include_tasks: packages.yml

Each included file contains its own list of tasks. Ansible executes the included task lists in the order they are included.

8. Using include_tasks with Conditions

You can use the when condition with include_tasks to decide whether a task file should be included.

---
- name: Conditional task inclusion
  hosts: ansible-client
  become: true

  tasks:
    - name: Include Ubuntu configuration tasks
      ansible.builtin.include_tasks: ubuntu_tasks.yml
      when: ansible_facts['distribution'] == "Ubuntu"

In this example, Ansible includes ubuntu_tasks.yml only when the target host's distribution is Ubuntu.

Remember: include_tasks is dynamic inclusion. The include is processed during playbook execution, so conditions and variables can determine whether the task file is included.

9. Important Points

Point Details
File format Included task files are normally YAML files.
Task structure The included file contains a list of tasks, not a complete play.
Execution Tasks execute on the hosts selected by the main play.
Privilege escalation The main play's become: true applies to included tasks unless overridden.
Dynamic inclusion The task file is included during playbook execution.
Reusability The same task file can be included from multiple playbooks.
Common mistake: Do not place hosts: or tasks: inside the included task file. Those belong to a playbook. An included task file should contain task definitions directly.

10. Practical Project: Application Setup Using Separate Task Files

Objective

Configure an application directory structure on the Ubuntu client using separate task files.

Directory structure:

application-project/
├── main.yml
├── directories.yml
├── files.yml
└── permissions.yml

directories.yml

---
- name: Create application directory
  ansible.builtin.file:
    path: /opt/webapp
    state: directory

- name: Create configuration directory
  ansible.builtin.file:
    path: /opt/webapp/config
    state: directory

files.yml

---
- name: Create application configuration
  ansible.builtin.copy:
    dest: /opt/webapp/config/app.conf
    content: |
      APP_NAME=LearningLabs
      APP_ENV=development
    mode: '0644'

permissions.yml

---
- name: Set application directory permissions
  ansible.builtin.file:
    path: /opt/webapp
    state: directory
    mode: '0755'
    recurse: true

main.yml

---
- name: Configure web application
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directories
      ansible.builtin.include_tasks: directories.yml

    - name: Create application files
      ansible.builtin.include_tasks: files.yml

    - name: Configure permissions
      ansible.builtin.include_tasks: permissions.yml

Execute:

ansible-playbook main.yml

Expected Result

The target Ubuntu container should contain:

/opt/webapp/
└── config/
    └── app.conf

The configuration file should contain the application name and environment values defined in files.yml.

Why Do We Use Ansible include_tasks?

We use include_tasks to divide large playbooks into smaller, manageable task files.

In real-world automation, a server configuration may involve user management, package installation, directory creation, application configuration, and permission management.

Keeping every operation in one playbook makes maintenance difficult. With include_tasks, we can organize these operations into separate files and include them when required.

For example, an application deployment playbook can include separate task files for installing dependencies, configuring the application, and preparing directories.

This improves code organization, maintainability, and reusability across Ansible projects.
