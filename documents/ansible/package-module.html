Ansible Package Module

In this lab, you will learn how to use the Ansible Package module to manage software packages. You will create playbooks to install, remove and update packages, and understand how package management can be automated across multiple managed systems.

1. What Is the Package Module?

Ansible provides the ansible.builtin.package module to manage software packages on different Linux distributions.

Linux distributions do not all use the same package manager. Ubuntu and Debian use APT, while Red Hat-based distributions use DNF or YUM.

Normally, you would need to use a distribution-specific package management module. The Package module provides a common interface for basic package operations.

Ansible identifies the appropriate package manager on the managed system and uses it to perform the requested operation.

Important: The Package module is a generic interface. On Ubuntu, it uses the underlying APT package management system. It does not replace APT or provide every APT-specific parameter.

2. Package Module Syntax

The basic structure of the Package module looks like this: 

- name: Install a package
  ansible.builtin.package:
    name: curl
    state: present

ansible.builtin.package identifies the module. The name parameter specifies the package, and state defines the required package state.

3. Important Package Module Parameters

name

Specifies the package that Ansible should manage. You can specify one package or a list of packages.

Example with a single package:

name: curl

Example with multiple packages:

name:
  - curl
  - wget
  - unzip

When a list is provided, Ansible applies the requested state to each package in the list.

state

Specifies the desired state of the package. Ansible checks the current package state and performs the required operation.

Common state values:

  • present – Ensures that the package is installed.
  • absent – Ensures that the package is removed.
  • latest – Ensures that the latest available version is installed.

For example, state: present does not necessarily upgrade an already installed package. It ensures that the package exists on the system.

use

The use parameter can specify which package manager Ansible should use instead of relying on automatic detection.

This parameter is useful when you need to explicitly select a supported package manager. 

- name: Install curl using APT
  ansible.builtin.package:
    name: curl
    state: present
    use: apt

Since this lab uses Ubuntu, apt selects the APT package manager.

The Package module supports only the common package management interface. Parameters such as update_cache, cache_valid_time and upgrade belong to package-manager-specific modules such as ansible.builtin.apt.

4. Install a Single Package

Create a playbook named install-package.yml. In this example, you will install curl using the generic Package module. 

---
- name: Install Curl
  hosts: all
  become: true

  tasks:
    - name: Ensure curl is installed
      ansible.builtin.package:
        name: curl
        state: present

Understanding the Playbook

hosts: all targets all managed hosts defined in the inventory.

become: true enables privilege escalation. Package installation normally requires administrative permissions.

ansible.builtin.package calls the generic package management module.

name: curl specifies the package to install.

state: present ensures that curl is installed. If it is already installed, Ansible does not reinstall it.

5. Install Multiple Packages

You can install several packages using a single Package module task. This is useful when configuring a new server that requires multiple software dependencies.

Create install-multiple-packages.yml. 

---
- name: Install Multiple Packages
  hosts: all
  become: true

  tasks:
    - name: Install administration tools
      ansible.builtin.package:
        name:
          - curl
          - wget
          - unzip
          - tree
          - htop
        state: present

Understanding the Playbook

The name parameter contains five package names. Ansible processes the list using the package manager available on the managed system.

state: present ensures that every listed package is installed.

If one or more packages are missing, Ansible installs the missing packages. Packages that are already installed remain unchanged.

6. Remove a Package

The Package module can also remove software. Create remove-package.yml. 

---
- name: Remove Package
  hosts: all
  become: true

  tasks:
    - name: Remove curl
      ansible.builtin.package:
        name: curl
        state: absent

Understanding the Playbook

name: curl identifies the package that must be removed.

state: absent ensures that curl is not installed on the managed system.

If curl is already absent, Ansible does not need to remove it again.

7. Ensure the Latest Package Version Is Installed

The Package module also supports state: latest. This ensures that the latest version available through the configured package repositories is installed.

Create latest-package.yml. 

---
- name: Install Latest Curl Version
  hosts: all
  become: true

  tasks:
    - name: Ensure curl is at the latest available version
      ansible.builtin.package:
        name: curl
        state: latest

Understanding the Playbook

state: latest checks the available package version and upgrades the package when a newer version is available.

If the installed version is already the latest available version, no upgrade is required.

The latest version depends on the configured package repositories. This task does not guarantee that the package is the newest version released by the software vendor.

8. Idempotency in the Package Module

Idempotency means that repeatedly executing the same playbook should not make unnecessary changes when the system already matches the desired configuration.

Consider this task:

- name: Ensure curl is installed
  ansible.builtin.package:
    name: curl
    state: present

When curl is not installed, Ansible installs it and reports changed.

When curl is already installed, Ansible leaves it unchanged and normally reports ok.

This makes the Package module useful for repeatable server configuration and automation.

9. Package Module vs APT Module

Both modules can install and remove packages on Ubuntu. However, they are designed for different levels of package management control.

Package Module

- name: Install curl
  ansible.builtin.package:
    name: curl
    state: present

The Package module provides a generic interface. It is useful when you want a playbook to work across different Linux distributions without changing basic package installation tasks.

APT Module

- name: Install curl and refresh package cache
  ansible.builtin.apt:
    name: curl
    state: present
    update_cache: true
    cache_valid_time: 3600

The APT module is designed specifically for Debian-based distributions. It provides additional APT-specific parameters for cache management, upgrades and package operations.

When should you use each module?
  • Use package for basic package operations when you want a generic interface.
  • Use apt when you need Ubuntu-specific APT functionality.

10. Practical Project: Ubuntu Server Base Software Setup

In this project, you will automate the installation of standard software packages required on an Ubuntu server.

The goal is to maintain a consistent set of administration tools across all managed servers using the generic Package module.

Project Requirements

  • Use an Ansible inventory to identify the target servers.
  • Install curl for HTTP requests.
  • Install wget for downloading files.
  • Install unzip for extracting archives.
  • Install tree for directory structure visualization.
  • Install htop for process monitoring.
  • Install git for source code management.
  • Install vim for text editing.
  • Ensure the required packages remain installed.

Step 1: Create the Project Directory

mkdir -p ubuntu-base-setup
cd ubuntu-base-setup

Step 2: Create the Inventory File

Create a file named inventory.ini. 

[ubuntu_servers]
192.168.1.101 ansible_user=ubuntu
192.168.1.102 ansible_user=ubuntu

Replace the example IP addresses and username with the connection details of your managed Ubuntu servers.

Step 3: Create the Main Playbook

Create a file named ubuntu-base-setup.yml. 

---
- name: Configure Ubuntu Base Software
  hosts: all
  become: true

  tasks:

    - name: Install standard administration packages
      ansible.builtin.package:
        name:
          - curl
          - wget
          - unzip
          - tree
          - htop
          - git
          - vim
        state: present

Step 4: Understand the Project Playbook

The playbook contains one package installation task. It defines seven required software packages in a YAML list.

ansible.builtin.package manages the package installation using the package manager available on the managed system.

state: present ensures that all seven packages are installed.

become: true allows Ansible to perform the installation with administrative permissions.

The playbook can be executed repeatedly. Packages that are already installed do not need to be installed again.

Step 5: Validate the Playbook

Check the playbook syntax before executing it. 

ansible-playbook -i inventory.ini ubuntu-base-setup.yml --syntax-check

If the YAML syntax and playbook structure are valid, Ansible displays a syntax OK message.

Step 6: Execute the Playbook

ansible-playbook -i inventory.ini ubuntu-base-setup.yml

Ansible connects to the managed servers and ensures that all seven packages are installed.

Step 7: Execute the Playbook Again

Run the same playbook again: 

ansible-playbook -i inventory.ini ubuntu-base-setup.yml

Since the packages are already installed, the installation task should report ok instead of changed, provided the package state has not changed.

Project completed: You have automated the installation of standard Ubuntu administration packages using the Ansible Package module.

Why Do We Use the Ansible Package Module?

Linux distributions use different package management systems. Ubuntu uses APT, while Red Hat-based distributions use DNF or YUM. This creates a challenge when administrators manage servers running different Linux distributions.

The Ansible Package module provides a common interface for basic package management operations. Instead of writing different package installation tasks for each supported package manager, you can use the same module structure.

1. Distribution-Independent Package Management

Consider an organization that manages Ubuntu and Red Hat servers. Both environments require curl to be installed.

Without the generic Package module, you would typically write an APT task for Ubuntu and a DNF task for Red Hat. The Package module allows you to write one basic package installation task that Ansible can use with the appropriate package manager.

This reduces distribution-specific differences in basic package management playbooks.

2. Reusable Playbooks

Reusability is important in automation. A playbook that installs basic packages can be reused across different environments without rewriting the package management task for each supported Linux distribution.

For example, a standard server configuration playbook may require curl, wget, unzip and Git. These package requirements can be defined once and reused across supported systems.

3. Consistent Software Installation

Organizations often require the same administration tools on every server. Missing packages can interrupt deployment scripts, monitoring tools and maintenance activities.

The Package module allows administrators to define the required package list and ensure that every selected server has the expected software installed.

4. Automated Package Removal

Package management is not limited to installation. Administrators also need to remove unnecessary or unwanted software from servers.

Using state: absent, the Package module can ensure that a package is not installed. This is useful when standardizing server software and removing packages that are no longer required.

5. Idempotent Automation

Repeated execution is common in configuration management. A playbook may run during initial server provisioning and again during later maintenance.

The Package module checks whether the requested package state is already satisfied. With state: present, it installs a missing package but does not unnecessarily reinstall an existing package.

This makes package management predictable and reduces unnecessary changes during repeated playbook executions.

6. When Should You Use the Package Module Instead of APT?

Use the Package module when you need basic package operations and want the same playbook structure to work across multiple supported Linux distributions.

Use the APT module when you specifically need APT functionality, such as refreshing the package cache, controlling cache validity, managing repository configuration or performing APT-specific upgrade operations.

7. Why Is This Important for a DevOps Engineer?

DevOps engineers frequently work with different Linux distributions across development, testing and production environments.

A generic package management interface helps create reusable automation, standardize software installations and reduce distribution-specific playbook changes.

Understanding the Package module also helps you decide when a generic Ansible module is sufficient and when a distribution-specific module is required.
