Ansible Lineinfile Module

Learn how to add, modify, replace, and remove individual lines inside configuration files using Ansible playbooks.

1. What Is the Lineinfile Module?

The ansible.builtin.lineinfile module manages individual lines inside files. It can add a new line, modify an existing line, remove a line, or insert a line at a specific position.

In Linux administration, configuration files contain settings that control how applications and services behave. Administrators frequently need to update these settings.

Instead of manually opening a file and editing it, Ansible can perform these changes consistently through a playbook.

Important: The lineinfile module is designed to manage individual lines. For managing larger multiline sections, use the blockinfile module.

2. How Does It Work?

Consider the following application configuration file:

# Application Configuration
APP_NAME=learning-labs
APP_PORT=5000
APP_ENV=development

Suppose you want to change the application port from 5000 to 8080.

Using lineinfile, Ansible can find the line containing APP_PORT and replace it with the required value.

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=development

Ansible checks the file before making changes. If the desired configuration already exists, it does not unnecessarily modify the file again.

3. Basic Playbook Structure

---
- name: Manage configuration file
  hosts: ansible-client
  become: true

  tasks:
    - name: Add application configuration
      ansible.builtin.lineinfile:
        path: /tmp/app.conf
        line: "APP_PORT=8080"
        state: present

Important fields:

  • hosts: Specifies the target host.
  • connection: Uses a local connection.
  • become: Enables privilege escalation.
  • path: Specifies the file to modify.
  • line: Specifies the line to add or replace.
  • state: Specifies whether the line should exist.

4. Important Parameters

Parameter Description
path Absolute path of the file to modify. Required.
line The exact line to add or use as replacement content.
regexp Regular expression used to find an existing line.
state present ensures the line exists. absent removes matching lines.
create Creates the file if it does not exist. Default is false.
backup Creates a backup of the original file before modification.
insertafter Inserts the line after a matching expression or at EOF.
insertbefore Inserts the line before a matching expression or at BOF.
firstmatch Uses the first matching insertion location instead of the last.
backrefs Uses captured groups from regexp inside the replacement line.
mode Sets file permissions when the file is created or modified.

5. Adding a New Line

The simplest use case is adding a configuration line to a file. If the line already exists, Ansible will not add another identical line.

Create add-line.yml:

---
- name: Add a configuration line
  hosts: ansible-client
  become: true

  tasks:
    - name: Add application port
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        line: "APP_PORT=8080"
        state: present
        create: true

If the file does not exist, create: true creates it. The parent directory must already exist.

6. Replacing an Existing Line Using Regexp

The regexp parameter searches for an existing line. When a match is found, Ansible replaces that line with the content specified by line.

Suppose the file contains:

APP_NAME=learning-labs
APP_PORT=5000
APP_ENV=development

Playbook:

---
- name: Update application port
  hosts: localhost
  connection: local
  become: true

  tasks:
    - name: Change application port
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        regexp: '^APP_PORT='
        line: "APP_PORT=8080"
        state: present

Result:

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=development
Remember: If the regular expression does not match any existing line and state: present is used, Ansible adds the specified line to the file.

7. Removing a Line

Use state: absent to remove lines matching the specified regular expression. 

---
- name: Remove development configuration
  hosts: localhost
  connection: local
  become: true

  tasks:
    - name: Remove development environment setting
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        regexp: '^APP_ENV='
        state: absent

Every line matching the regular expression is removed.

8. Inserting a Line at a Specific Position

Sometimes a configuration line must be placed before or after another line. The insertbefore and insertafter parameters control its position.

Using insertafter

---
- name: Insert configuration after application name
  hosts: ansible-client
  become: true

  tasks:
    - name: Add application owner
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        line: "APP_OWNER=admin"
        insertafter: '^APP_NAME='
        state: present

Using insertbefore

---
- name: Insert configuration before application port
  hosts: ansible-client
  become: true

  tasks:
    - name: Add application version
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        line: "APP_VERSION=1.0"
        insertbefore: '^APP_PORT='
        state: present

Special insertion positions

  • EOF: End of the file.
  • BOF: Beginning of the file.

9. Creating a Backup Before Modification

Configuration changes can affect application behavior. You can create a backup before modifying the original file. 

---
- name: Update configuration with backup
  hosts: ansible-client
  become: true

  tasks:
    - name: Update application environment
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        regexp: '^APP_ENV='
        line: "APP_ENV=production"
        state: present
        backup: true

When Ansible modifies the file, it creates a backup containing the previous file content.

10. Using Backreferences

The backrefs parameter allows you to capture part of an existing line using regular expression groups and reuse that captured content in the replacement line.

Suppose the configuration contains:

APP_PORT=5000

Playbook:

---
- name: Update configuration using backreferences
  hosts: ansible-client
  become: true

  tasks:
    - name: Update application port
      ansible.builtin.lineinfile:
        path: /tmp/ansible-lineinfile-lab/app.conf
        regexp: '^(APP_PORT=).*'
        line: '\g<1>8080'
        backrefs: true

Result:

APP_PORT=8080
Important: When backrefs: true is enabled, the replacement happens only if the regular expression matches. If no match is found, Ansible does not insert a new line.

11. Understanding Idempotency

Idempotency means that running the same playbook multiple times produces the same desired result without making unnecessary changes.

Consider this task:

- name: Ensure application port
  ansible.builtin.lineinfile:
    path: /tmp/ansible-lineinfile-lab/app.conf
    regexp: '^APP_PORT='
    line: "APP_PORT=8080"
    state: present
  • First run: Ansible adds or updates the configuration.
  • Second run: No change is required if the desired line exists.
  • Third run: The configuration remains unchanged.

This behavior is important when automating configuration management across multiple servers.

12. Practical Project: Manage an Application Configuration File

In this project, you will create and manage an application configuration file using the lineinfile module.

Project Requirements

  • Create an application configuration file.
  • Configure the application name.
  • Set the application port to 8080.
  • Set the environment to production.
  • Add an application owner.
  • Remove an unwanted debug setting.
  • Create a backup before modifying the configuration.
  • Ensure the playbook is idempotent.

Step 1: Create the Project Directory

Create a playbook named application-config.yml.

Step 2: Write the Complete Playbook

---
- name: Manage application configuration
  hosts: ansible-client
  become: true

  vars:
    config_dir: /tmp/ansible-lineinfile-lab
    config_file: /tmp/ansible-lineinfile-lab/app.conf

  tasks:

    - name: Create configuration directory
      ansible.builtin.file:
        path: "{{ config_dir }}"
        state: directory
        mode: '0755'

    - name: Create initial configuration file
      ansible.builtin.copy:
        dest: "{{ config_file }}"
        content: |
          APP_NAME=learning-labs
          APP_PORT=5000
          APP_ENV=development
          APP_DEBUG=true
        force: false
        mode: '0644'

    - name: Ensure application name
      ansible.builtin.lineinfile:
        path: "{{ config_file }}"
        regexp: '^APP_NAME='
        line: "APP_NAME=learning-labs"
        state: present
        backup: true

    - name: Update application port
      ansible.builtin.lineinfile:
        path: "{{ config_file }}"
        regexp: '^APP_PORT='
        line: "APP_PORT=8080"
        state: present
        backup: true

    - name: Update environment
      ansible.builtin.lineinfile:
        path: "{{ config_file }}"
        regexp: '^APP_ENV='
        line: "APP_ENV=production"
        state: present

    - name: Add application owner
      ansible.builtin.lineinfile:
        path: "{{ config_file }}"
        regexp: '^APP_OWNER='
        line: "APP_OWNER=admin"
        state: present

    - name: Remove debug setting
      ansible.builtin.lineinfile:
        path: "{{ config_file }}"
        regexp: '^APP_DEBUG='
        state: absent

    - name: Display final configuration
      ansible.builtin.debug:
        msg: "Application configuration has been updated successfully."

Step 3: Expected Configuration

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=production
APP_OWNER=admin

Step 4: Verify the Result

Create a second playbook named verify-config.yml. 

---
- name: Verify application configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Read application configuration
      ansible.builtin.command:
        argv:
          - cat
          - /tmp/ansible-lineinfile-lab/app.conf
      register: config_output
      changed_when: false

    - name: Display configuration
      ansible.builtin.debug:
        var: config_output.stdout

Step 5: Test Idempotency

Run the project playbook more than once and observe the task results. After the configuration reaches the desired state, the lineinfile tasks should report no further changes.

Project outcome: You have automated application configuration management, including adding, replacing, and removing configuration lines without manually editing the file.

Why Do We Use the Ansible Lineinfile Module?

Linux servers depend on configuration files to control applications, services, networking, security settings, authentication, and system behavior. These files frequently require updates during application deployments and routine server administration.

Traditionally, an administrator might connect to every server, open the required configuration file, locate a particular setting, modify it, and save the file. When the same change must be performed on several servers, this approach becomes repetitive and increases the possibility of human error.

The Ansible lineinfile module automates these individual configuration changes. An administrator can define the desired configuration once in a playbook and apply it consistently across the required systems.

Practical Reasons to Use It

  • Automated configuration changes: Update application settings without manually opening configuration files.
  • Consistent configurations: Maintain the same required configuration across multiple managed servers.
  • Idempotent execution: Avoid repeatedly adding duplicate configuration lines.
  • Configuration cleanup: Remove unwanted settings such as obsolete debug entries.
  • Deployment automation: Update application ports, environment variables stored in configuration files, and other individual settings during deployments.
  • Backup support: Preserve the previous file before making changes.
  • Reduced manual effort: Apply configuration changes to many systems through a single automation workflow.

Real-World DevOps Example

Imagine an organization managing 50 Ubuntu application servers. A new application release requires changing the application port from 5000 to 8080 on every server.

Instead of logging in to all 50 servers individually, an administrator can write an Ansible playbook using lineinfile and execute it against the managed inventory.

Ansible checks each server, updates the required line, and leaves systems that already have the correct setting unchanged.

This is why lineinfile is useful in configuration management, infrastructure automation, and repeatable DevOps workflows.

Remember: Use lineinfile when you need to manage individual lines. For managing complete files, consider the copy or template modules. For managing multiline sections, use blockinfile.
