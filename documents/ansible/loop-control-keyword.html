Ansible loop_control Keyword

The loop_control keyword allows you to customize how Ansible handles loop iterations. You can control the displayed item, change the loop variable name, track the current iteration number, and introduce a delay between iterations.

1. Why Do We Need loop_control?

In the previous lesson, you learned how to use loop to execute a task for multiple items.

By default, Ansible uses the variable item for the current loop value. It also displays loop results in its task output.

When working with large lists or complex data, you may want more control over how each iteration behaves and appears in the output.

This is where loop_control is useful.

2. Basic Syntax

- name: Task description
  ansible.builtin.module_name:
    parameter: "{{ item }}"
  loop:
    - value1
    - value2
    - value3
  loop_control:
    label: "{{ item }}"

The loop_control section is placed at the same indentation level as loop.

3. Control Output Using label

The label option controls what Ansible displays for each loop iteration in the task output.

Consider a loop containing application configuration details: 

---
- name: Configure applications
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directories
      ansible.builtin.file:
        path: "{{ item.path }}"
        state: directory
        mode: '0755'
      loop:
        - name: frontend
          path: /opt/frontend
          owner: root
        - name: backend
          path: /opt/backend
          owner: root
        - name: database
          path: /opt/database
          owner: root
      loop_control:
        label: "{{ item.name }}"

Here, each loop item is a dictionary containing multiple fields. The label displays only the application name instead of the complete dictionary.

The task output identifies iterations using labels such as: 

frontend
backend
database
Important: The label option changes only how loop items are displayed. It does not change the actual task input or hide sensitive values from Ansible's logs in a security-safe way.

4. Change the Default Loop Variable Using loop_var

By default, Ansible stores the current loop value in a variable named item.

The loop_var option allows you to use a different variable name. 

---
- name: Configure application directories
  hosts: ansible-client
  become: true

  tasks:
    - name: Create directories
      ansible.builtin.file:
        path: "/opt/{{ application }}"
        state: directory
        mode: '0755'
      loop:
        - frontend
        - backend
        - database
      loop_control:
        loop_var: application

Instead of using item, the task now uses application.

Iteration Default variable Custom variable
1 item = frontend application = frontend
2 item = backend application = backend
3 item = database application = database

5. Track the Iteration Number Using index_var

The index_var option stores the current loop iteration index in a variable.

The index starts at zero. 

---
- name: Display loop indexes
  hosts: ansible-client
  become: true

  tasks:
    - name: Display each application
      ansible.builtin.debug:
        msg: "Index {{ app_index }}: {{ item }}"
      loop:
        - frontend
        - backend
        - database
      loop_control:
        index_var: app_index

The output messages will contain these indexes: 

Index 0: frontend
Index 1: backend
Index 2: database

If you want numbering to start from one, you can add one to the index when displaying it. 

- name: Display human-readable numbering
  ansible.builtin.debug:
    msg: "Application {{ app_index + 1 }}: {{ item }}"
  loop:
    - frontend
    - backend
    - database
  loop_control:
    index_var: app_index

6. Add a Delay Between Iterations Using pause

The pause option introduces a delay between loop iterations. The value is specified in seconds. 

---
- name: Process applications with a delay
  hosts: ansible-client
  become: true

  tasks:
    - name: Display application name
      ansible.builtin.debug:
        msg: "Processing {{ item }}"
      loop:
        - frontend
        - backend
        - database
      loop_control:
        pause: 3

Ansible waits three seconds between consecutive iterations. It does not need to wait before the first iteration.

Use case: A delay can be useful when an external service has rate limits or when operations should be spaced out. A delay does not guarantee that the external service is ready.

7. Use Multiple loop_control Options Together

You can combine multiple options under the same loop_control section. 

---
- name: Demonstrate multiple loop controls
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directories
      ansible.builtin.file:
        path: "/opt/{{ app_name }}"
        state: directory
        mode: '0755'
      loop:
        - frontend
        - backend
        - database
      loop_control:
        loop_var: app_name
        index_var: app_index
        label: "{{ app_name }}"
        pause: 1

This task:

  • Uses app_name instead of the default item.
  • Stores the iteration index in app_index.
  • Displays the application name as the loop label.
  • Waits one second between iterations.

8. Important loop_control Options

Option Purpose
label Controls the item representation displayed in task output.
loop_var Changes the variable name used for the current item.
index_var Stores the current zero-based iteration index.
pause Adds a delay in seconds between iterations.
extended Enables additional loop information through the ansible_loop variable.
extended_allitems Controls whether the extended loop information includes the complete list of items.

9. Practical Lab: Configure Multiple Application Components

Scenario

You are preparing an application server with three components: frontend, backend, and database. You need to create directories and display their iteration numbers.

Create this playbook:

---
- name: Configure application components
  hosts: ansible-client
  become: true

  tasks:
    - name: Create component directories
      ansible.builtin.file:
        path: "/opt/{{ component }}"
        state: directory
        mode: '0755'
      loop:
        - frontend
        - backend
        - database
      loop_control:
        loop_var: component
        index_var: component_index
        label: "{{ component }}"
        pause: 1

    - name: Display component information
      ansible.builtin.debug:
        msg: "Component {{ component_index + 1 }}: {{ component }}"
      loop:
        - frontend
        - backend
        - database
      loop_control:
        loop_var: component
        index_var: component_index
        label: "{{ component }}"

Run from ansible-controller:

ansible-playbook application-components.yml

Expected behavior:

  • Three directories are created under /opt.
  • The loop variable is named component.
  • The index variable starts at zero.
  • The first task waits one second between iterations.
  • The second task displays component numbers starting from one.

Why Do We Use the Ansible loop_control Keyword?

In real DevOps automation, loops often process large lists of servers, applications, packages, users, and configuration objects. The default loop behavior may not always provide the clarity or control required for complex playbooks.

The loop_control keyword allows you to customize individual loop executions. You can assign meaningful variable names, track iteration indexes, simplify task output, and introduce delays between operations.

For example, when configuring multiple application components, using a descriptive loop variable such as component makes the playbook easier to understand than repeatedly using the generic variable item.

These options improve playbook readability, make execution output easier to interpret, and provide better control when automating repetitive infrastructure operations.
