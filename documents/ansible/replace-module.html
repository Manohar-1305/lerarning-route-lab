Ansible Replace Module

Learn how to find and replace text patterns inside files using regular expressions and Ansible playbooks.

1. What Is the Replace Module?

The ansible.builtin.replace module searches for text matching a regular expression and replaces every matching occurrence with the specified replacement text.

It is useful when you need to update existing values, change configuration entries, replace outdated text, or remove unwanted content from files.

Unlike lineinfile, which manages individual lines, replace works with regular-expression patterns across the file.

Important: The replace module does not require the existing text to occupy an entire line. It can replace matching text within a line or across multiple lines, depending on the regular expression.

2. Understanding How Replace Works

Consider this configuration file:

APP_NAME=learning-labs
APP_PORT=5000
APP_ENV=development
APP_DEBUG=true

Suppose you want to replace the application port from 5000 to 8080.

The replace module searches for the matching text and updates it.

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=development
APP_DEBUG=true

You can also replace multiple occurrences of the same text throughout a file.

3. Basic Playbook Structure

---
- name: Replace configuration values
  hosts: ansible-client
  become: true

  tasks:
    - name: Update application port
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: 'APP_PORT=5000'
        replace: 'APP_PORT=8080'

Important fields:

  • hosts: Specifies the target managed host.
  • become: Enables privilege escalation.
  • path: Specifies the file to modify.
  • regexp: Defines the pattern to search for.
  • replace: Defines the replacement text.

4. Important Parameters

Parameter Description
path Absolute path of the file to modify. Required.
regexp Regular expression used to find matching text. Required.
replace Text used to replace matching content. Defaults to an empty string.
backup Creates a backup before modifying the file.
before Limits the replacement operation to content before a matching expression.
after Limits the replacement operation to content after a matching expression.
validate Validates the temporary modified file before replacing the original file.
owner Sets the file owner.
group Sets the file group.
mode Sets file permissions.
attributes Sets file attributes using the supported file attribute flags.

5. Replacing a Specific Configuration Value

You can use an exact regular expression to replace a configuration value.

Create replace-port.yml:

---
- name: Update application port
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace application port
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: 'APP_PORT=5000'
        replace: 'APP_PORT=8080'

Before execution:

APP_PORT=5000

After execution:

APP_PORT=8080

6. Replacing Values Using Regular Expressions

Regular expressions allow you to match patterns instead of searching for one exact value.

For example, the following expression matches any line that begins with APP_PORT=, regardless of its current port value. 

---
- name: Update application port dynamically
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace application port
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^APP_PORT=.*$'
        replace: 'APP_PORT=8080'

This replaces the complete matching line, whether the existing value is 5000, 5001, or another value.

Useful Regular Expression Patterns

Pattern Meaning
^APP_PORT= Matches text beginning with APP_PORT=.
.* Matches zero or more characters.
^ Matches the beginning of a line.
$ Matches the end of a line.
[0-9]+ Matches one or more digits.
old|new Matches either old or new.

7. Replacing Multiple Occurrences

The replace module replaces all occurrences matching its regular expression, not just the first occurrence.

Suppose the file contains:

SERVER=old-server
BACKUP_SERVER=old-server
MONITOR_SERVER=old-server

Playbook:

---
- name: Update server references
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace old server name
      ansible.builtin.replace:
        path: /tmp/servers.conf
        regexp: 'old-server'
        replace: 'new-server'

Result:

SERVER=new-server
BACKUP_SERVER=new-server
MONITOR_SERVER=new-server

8. Removing Matching Text

You can remove matching content by setting the replace parameter to an empty string.

Suppose the file contains:

APP_NAME=learning-labs
APP_DEBUG=true
APP_PORT=8080

Playbook:

---
- name: Remove debug configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Remove debug setting
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^APP_DEBUG=.*\n?'
        replace: ''

Result:

APP_NAME=learning-labs
APP_PORT=8080
Important: Carefully test regular expressions before applying them to important files. A broad expression can remove more content than intended.

9. Replacing Text Within a Specific Section

The before and after parameters restrict where the replacement operation is performed.

Consider this file:

[application]
PORT=5000
ENV=development

[database]
PORT=5432
HOST=localhost

Suppose you want to change the application port without changing the database port. 

---
- name: Update application section
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace application port only
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^PORT=5000$'
        replace: 'PORT=8080'
        before: '^\[database\]'

Result:

[application]
PORT=8080
ENV=development

[database]
PORT=5432
HOST=localhost

The before parameter limits the operation to content before the database section.

10. Creating a Backup Before Modification

Use backup: true to preserve the original file before replacing its content. 

---
- name: Update configuration with backup
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace application environment
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^APP_ENV=.*$'
        replace: 'APP_ENV=production'
        backup: true

11. Validating a File Before Applying Changes

The validate parameter runs a validation command against the temporary modified file before Ansible replaces the original file. 

---
- name: Validate configuration before applying
  hosts: ansible-client
  become: true

  tasks:
    - name: Replace application port
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^APP_PORT=.*$'
        replace: 'APP_PORT=8080'
        validate: '/usr/bin/test -s %s'

This example checks that the temporary file is not empty. For actual application configurations, use the application's own configuration validation command.

12. Understanding Idempotency

Idempotency means that executing the same playbook repeatedly produces the same desired result without unnecessary changes. 

---
- name: Ensure application port
  hosts: ansible-client
  become: true

  tasks:
    - name: Set application port to 8080
      ansible.builtin.replace:
        path: /tmp/app.conf
        regexp: '^APP_PORT=.*$'
        replace: 'APP_PORT=8080'
  • First execution: The existing port value is replaced.
  • Second execution: The desired value already exists.
  • Third execution: No further modification is required.

13. Practical Project: Application Configuration Migration

In this project, you will migrate an existing application configuration file to a new configuration standard.

Project Requirements

  • Create an application configuration file.
  • Replace the old application port.
  • Change the application environment.
  • Replace an old server hostname everywhere in the file.
  • Remove the debug setting.
  • Update a specific section without changing another section.
  • Create backups before modifications.
  • Verify the final configuration.

Step 1: Create the Complete Playbook

Create application-migration.yml on the controller.

---
- name: Migrate application configuration
  hosts: ansible-client
  become: true

  vars:
    config_dir: /tmp/ansible-replace-lab
    config_file: /tmp/ansible-replace-lab/app.conf

  tasks:

    - name: Create configuration directory
      ansible.builtin.file:
        path: "{{ config_dir }}"
        state: directory
        mode: '0755'

    - name: Create initial application configuration
      ansible.builtin.copy:
        dest: "{{ config_file }}"
        content: |
          APP_NAME=learning-labs
          APP_PORT=5000
          APP_ENV=development
          APP_DEBUG=true
          SERVER=old-server
          BACKUP_SERVER=old-server

          [database]
          DB_HOST=old-database
          DB_PORT=5432
        force: false
        mode: '0644'

    - name: Update application port
      ansible.builtin.replace:
        path: "{{ config_file }}"
        regexp: '^APP_PORT=.*$'
        replace: 'APP_PORT=8080'
        backup: true

    - name: Update application environment
      ansible.builtin.replace:
        path: "{{ config_file }}"
        regexp: '^APP_ENV=.*$'
        replace: 'APP_ENV=production'
        backup: true

    - name: Replace old server hostname
      ansible.builtin.replace:
        path: "{{ config_file }}"
        regexp: 'old-server'
        replace: 'new-server'

    - name: Remove debug configuration
      ansible.builtin.replace:
        path: "{{ config_file }}"
        regexp: '^APP_DEBUG=.*\n?'
        replace: ''

    - name: Update database hostname
      ansible.builtin.replace:
        path: "{{ config_file }}"
        regexp: '^DB_HOST=.*$'
        replace: 'DB_HOST=127.0.0.1'
        backup: true

    - name: Display completion message
      ansible.builtin.debug:
        msg: "Application configuration migration completed."

Step 2: Expected Configuration

APP_NAME=learning-labs
APP_PORT=8080
APP_ENV=production
SERVER=new-server
BACKUP_SERVER=new-server

[database]
DB_HOST=127.0.0.1
DB_PORT=5432

Step 3: Verify the Configuration

Create verify-config.yml on the controller.

---
- name: Verify migrated configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Read application configuration
      ansible.builtin.slurp:
        src: /tmp/ansible-replace-lab/app.conf
      register: config_content

    - name: Display final configuration
      ansible.builtin.debug:
        msg: "{{ config_content.content | b64decode }}"

Step 4: Test Idempotency

Execute the migration playbook again. Once all the required values are present, the replace tasks should report no further changes.

Project outcome: You have automated a configuration migration on the ansible-client Ubuntu host using regular expressions and the Ansible replace module.

Why Do We Use the Ansible Replace Module?

Configuration files often contain outdated values, application settings, hostnames, ports, and environment variables that need to be changed during infrastructure maintenance or application deployments.

When administrators manage multiple servers, manually searching for and replacing these values becomes repetitive. It also increases the risk of modifying the wrong setting or overlooking some occurrences.

The Ansible replace module automates this process using regular expressions. It searches for matching patterns and replaces all matching occurrences with the required content.

Practical Reasons to Use It

  • Configuration migration: Replace old application values with new values during deployment upgrades.
  • Hostname updates: Replace outdated server names throughout configuration files.
  • Port changes: Update application ports without manually editing files.
  • Configuration cleanup: Remove unwanted settings and obsolete configuration text.
  • Bulk replacements: Replace multiple matching occurrences in a single task.
  • Controlled modifications: Restrict changes to a particular section using before and after expressions.
  • Backup support: Preserve the original file before applying changes.

Real-World DevOps Example

Imagine an organization migrating its applications from an old server environment to a new infrastructure. Configuration files across 40 Ubuntu servers contain references to an old server hostname.

Instead of logging in to every server and manually replacing the hostname, an administrator can use the Ansible replace module to update all matching references through a single playbook.

The same approach can be used to update ports, remove deprecated settings, and migrate configuration values.

Remember: Use replace when you need to search and replace text patterns. Use lineinfile for individual line management, blockinfile for multiline sections, and template when managing an entire file from a template.
