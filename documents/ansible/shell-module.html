Ansible Shell Module

The Ansible Shell module executes commands on managed hosts through a shell environment. It supports shell features such as pipes, redirection, environment-variable expansion and command chaining.

1. What Is the Shell Module?

The ansible.builtin.shell module executes commands using the managed host's configured shell, normally /bin/sh.

Common use cases include:

  • Executing commands that require shell features.
  • Using pipes to pass output between commands.
  • Redirecting command output to files.
  • Expanding environment variables.
  • Running command sequences with conditional operators.
  • Executing scripts through a shell.
Important distinction: Use the Ansible Command module for ordinary commands that do not require shell features. Use the Shell module when you specifically need shell functionality.

2. How Does the Shell Module Work?

             Ansible Controller
             ------------------
             Playbook
                 |
                 |
             SSH Connection
                 |
                 v
             Managed Host
             -------------
             Shell Environment
                 |
                 v
             Execute Command
                 |
                 v
             Return Output

Ansible connects to the managed host, executes the supplied command through a shell and returns the command output and execution status.

3. Important Parameters

Parameter Description
cmd Command or shell command sequence to execute.
chdir Changes to the specified directory before executing the command.
creates Skips execution if the specified file already exists.
removes Executes only when the specified file exists.
executable Specifies the shell executable, such as /bin/bash.
stdin Supplies standard input to the command.
stdin_add_newline Controls whether a newline is appended to standard input.

4. Execute a Basic Shell Command

The following playbook displays the current date and time on the managed host.

Playbook: shell-basic.yml

---
- name: Execute basic shell command
  hosts: ansible-client
  become: true

  tasks:
    - name: Display current date
      ansible.builtin.shell:
        cmd: date

5. Execute Multiple Commands

You can execute multiple commands in a single task by separating them with shell operators.

Playbook: shell-multiple.yml

---
- name: Execute multiple shell commands
  hosts: ansible-client
  become: true

  tasks:
    - name: Display hostname and current directory
      ansible.builtin.shell:
        cmd: |
          hostname
          pwd
          whoami

6. Use Pipes

A pipe (|) passes the output of one command as input to another command.

Playbook: shell-pipe.yml

---
- name: Execute command using pipe
  hosts: ansible-client
  become: true

  tasks:
    - name: Count running processes
      ansible.builtin.shell:
        cmd: ps aux | wc -l

7. Redirect Output to a File

Shell redirection allows you to save command output into a file on the managed host.

Playbook: shell-redirection.yml

---
- name: Redirect command output
  hosts: ansible-client
  become: true

  tasks:
    - name: Save hostname to a file
      ansible.builtin.shell:
        cmd: hostname > /tmp/hostname-report.txt

8. Execute Commands in a Specific Directory

The chdir parameter changes the working directory before executing the shell command.

Playbook: shell-chdir.yml

---
- name: Execute command in specific directory
  hosts: ansible-client
  become: true

  tasks:
    - name: Create a report in the lab directory
      ansible.builtin.shell:
        cmd: pwd > working-directory.txt
        chdir: /tmp

9. Use the Creates Parameter

The creates parameter prevents a task from executing when a specified file already exists.

Playbook: shell-creates.yml

---
- name: Use creates parameter
  hosts: ansible-client
  become: true

  tasks:
    - name: Generate report only once
      ansible.builtin.shell:
        cmd: date > /tmp/first-run-report.txt
        creates: /tmp/first-run-report.txt

On the first execution, the file is created. On subsequent executions, Ansible skips the command because the file exists.

10. Use the Removes Parameter

The removes parameter executes a command only when the specified file exists.

Playbook: shell-removes.yml

---
- name: Use removes parameter
  hosts: ansible-client
  become: true

  tasks:
    - name: Remove temporary report when it exists
      ansible.builtin.shell:
        cmd: rm -f /tmp/temporary-report.txt
        removes: /tmp/temporary-report.txt

11. Execute Commands Using Bash

The executable parameter lets you select a specific shell instead of using the default shell.

Playbook: shell-bash.yml

---
- name: Execute command using Bash
  hosts: ansible-client
  become: true

  tasks:
    - name: Display Bash shell information
      ansible.builtin.shell:
        cmd: echo "Current shell: $BASH_VERSION"
        executable: /bin/bash

12. Capture Command Output

You can register the result of a Shell task in a variable and display it using the Debug module.

Playbook: shell-register.yml

---
- name: Capture shell command output
  hosts: ansible-client
  become: true

  tasks:
    - name: Get hostname
      ansible.builtin.shell:
        cmd: hostname
      register: hostname_result

    - name: Display hostname
      ansible.builtin.debug:
        var: hostname_result.stdout
Note: The register keyword is a playbook feature, not a Shell module parameter. The Debug module displays the captured output.

13. Practical Project: Linux Server Information Collector

Project Objective

Create a playbook that collects basic Linux server information, saves reports on the managed host and displays selected results.

Requirements:
  1. Collect the hostname.
  2. Collect the current date and time.
  3. Count the running processes.
  4. Collect disk usage information.
  5. Save the collected information into a report file.
  6. Display the report location.
Project playbook: server-information.yml 
---
- name: Collect Linux server information
  hosts: ansible-client
  become: true

  tasks:
    - name: Collect hostname
      ansible.builtin.shell:
        cmd: hostname
      register: hostname_result
      changed_when: false

    - name: Collect date and time
      ansible.builtin.shell:
        cmd: date
      register: date_result
      changed_when: false

    - name: Count running processes
      ansible.builtin.shell:
        cmd: ps aux | wc -l
      register: process_result
      changed_when: false

    - name: Collect disk usage
      ansible.builtin.shell:
        cmd: df -h /
      register: disk_result
      changed_when: false

    - name: Generate server information report
      ansible.builtin.shell:
        cmd: |
          {
            echo "SERVER INFORMATION REPORT"
            echo "========================="
            echo "Hostname: {{ hostname_result.stdout }}"
            echo "Date: {{ date_result.stdout }}"
            echo "Process count: {{ process_result.stdout }}"
            echo ""
            echo "Disk usage:"
            df -h /
          } > /tmp/server-information-report.txt

    - name: Display report location
      ansible.builtin.debug:
        msg: "Report created at /tmp/server-information-report.txt"

14. Important Considerations

  • Shell commands may behave differently across operating systems.
  • Use become: true when elevated privileges are required.
  • Use changed_when: false for read-only commands when appropriate.
  • Use creates or removes when they accurately represent whether a command needs to run.
  • Shell tasks are not automatically idempotent.
  • Avoid passing untrusted variables directly into shell commands because this can introduce command injection vulnerabilities.
  • Prefer dedicated Ansible modules whenever they can perform the required operation.

Why Do We Use the Ansible Shell Module?

In real-world DevOps environments, administrators sometimes need to execute commands that require shell capabilities, such as pipes, redirection, variable expansion and command chaining.

The Ansible Shell module allows these commands to be executed remotely through a playbook across multiple managed hosts.

For example, a DevOps engineer can collect system information, generate reports, execute existing shell scripts and automate specific operational tasks without manually logging in to every server.

However, shell commands can introduce security and idempotency problems when used incorrectly. Whenever a dedicated Ansible module exists for an operation, prefer that module over the Shell module.
