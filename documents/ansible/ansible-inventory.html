Ansible Inventory

Ansible Inventory defines the managed hosts and groups of hosts that Ansible can connect to and configure. It tells Ansible which systems are available for automation.

1. Why Do We Need an Inventory?

Your current lab has two containers:

  • ansible-controller: Runs Ansible playbooks.
  • ansible-client: The managed Ubuntu container.

Ansible needs to know which host it should connect to when executing a playbook.

The inventory provides this information. Instead of writing the target hostname directly into every command, you define it once and reference it through a group.

2. What Is an Ansible Inventory?

An inventory is a file or external data source containing information about managed hosts.

Ansible supports two main inventory approaches:

Inventory Type Description
Static Inventory Hosts are manually defined in a file.
Dynamic Inventory Hosts are discovered from external sources such as cloud platforms or infrastructure systems.

We will use a static inventory for this lab.

3. Create a Basic Inventory File

On your Ansible controller, create a project directory:

mkdir -p inventory-lab
cd inventory-lab

Create the inventory file using the vi editor:

vi inventory

Press i to enter INSERT mode and add the following configuration:

[lab]
ansible-client ansible_user=root

[ubuntu]
ansible-client

[all:vars]
ansible_connection=ssh
ansible_port=22

Press Esc, type :wq, and press Enter to save and exit.

Understanding the inventory:

Entry Purpose
[lab] Defines a group named lab.
ansible-client Your existing managed Ubuntu container.
ansible_user=root Specifies the SSH username.
[ubuntu] Defines another group containing the same client.
[all:vars] Defines connection variables inherited by all inventory hosts.
ansible_connection=ssh Uses SSH for connecting to the managed host.
ansible_port=22 Specifies the SSH port.
Important: Both groups reference the same ansible-client container. They do not create additional hosts or containers.

4. Understand Inventory Groups

Groups allow you to organize hosts by purpose or environment.

Your inventory contains two groups:

[lab]
ansible-client

[ubuntu]
ansible-client

The same host can belong to multiple groups. This does not create duplicate machines.

You can target either group in a playbook:

hosts: lab

Or:

hosts: ubuntu

5. Define Host Connection Variables

You can define connection variables directly beside the host entry.

[lab]
ansible-client ansible_user=root ansible_port=22

Common inventory variables include:

Variable Purpose
ansible_host IP address or hostname used for the connection.
ansible_user SSH username.
ansible_port SSH port. Default is 22.
ansible_ssh_private_key_file Path to the SSH private key.
ansible_connection Connection type used by Ansible.
Security: Do not store private key contents or plaintext passwords in an inventory file. Protect private keys with appropriate filesystem permissions and use Ansible Vault or another secrets-management solution for sensitive variables.

6. Validate the Inventory

Display all inventory hosts:

ansible-inventory -i inventory --list

Display the inventory group structure:

ansible-inventory -i inventory --graph

Display variables for the managed host:

ansible-inventory -i inventory --host ansible-client

Check the inventory structure. You should see both lab and ubuntu groups containing ansible-client.

7. Test Connectivity to the Client

Run the Ansible ping module against the lab group:

ansible lab -i inventory -m ansible.builtin.ping

You can also test the same client through the ubuntu group:

ansible ubuntu -i inventory -m ansible.builtin.ping
Remember: The Ansible ping module tests Ansible connectivity over the configured connection. It is not an ICMP network ping.

8. Use the Inventory in a Playbook

Create a file named main.yml in the same directory.

vi main.yml

Press i and add:

---
- name: Test Ansible inventory
  hosts: lab
  become: true

  tasks:
    - name: Display managed hostname
      ansible.builtin.command: hostname
      register: host_output
      changed_when: false

    - name: Display hostname result
      ansible.builtin.debug:
        var: host_output.stdout

Press Esc, type :wq, and press Enter.

Execute the playbook:

ansible-playbook -i inventory main.yml

The -i option tells Ansible which inventory file to use.

9. Understand Inventory Host Aliases

An inventory hostname can be the actual hostname or a logical alias mapped to an address.

Your current inventory uses the actual hostname:

[lab]
ansible-client

If your environment requires connecting through an IP address, you can use:

[lab]
ansible-client ansible_host=ACTUAL_CLIENT_IP
Important: ACTUAL_CLIENT_IP is a placeholder, not a working address. Keep your existing hostname-based configuration unless you have verified that an IP address is required.

10. Practical Project: Manage Your Ubuntu Client Through Inventory

Objective

Create an inventory file for your existing Ubuntu container lab and execute a playbook against the single managed client.

Project structure:

inventory-project/
├── inventory
└── main.yml

Step 1: Create the project directory

mkdir -p inventory-project
cd inventory-project

Step 2: Create the inventory file

vi inventory

Press i and add:

[lab]
ansible-client ansible_user=root

[ubuntu]
ansible-client

[all:vars]
ansible_connection=ssh
ansible_port=22

Press Esc, type :wq, and press Enter.

Step 3: Validate the inventory

ansible-inventory -i inventory --graph

Step 4: Test connectivity

ansible lab -i inventory -m ansible.builtin.ping

Step 5: Create main.yml

vi main.yml

Press i and add:

---
- name: Configure Ubuntu lab client
  hosts: lab
  become: true

  tasks:
    - name: Create lab directory
      ansible.builtin.file:
        path: /opt/ansible-inventory-lab
        state: directory
        mode: '0755'

    - name: Create inventory information file
      ansible.builtin.copy:
        dest: /opt/ansible-inventory-lab/info.txt
        content: |
          Managed by Ansible Inventory
          Host: {{ inventory_hostname }}
        mode: '0644'

    - name: Read inventory information
      ansible.builtin.command: cat /opt/ansible-inventory-lab/info.txt
      register: inventory_info
      changed_when: false

    - name: Display inventory information
      ansible.builtin.debug:
        var: inventory_info.stdout

Press Esc, type :wq, and press Enter.

Step 6: Execute the playbook

ansible-playbook -i inventory main.yml

Step 7: Verify the result

Create verify.yml:

vi verify.yml

Press i and add:

---
- name: Verify inventory configuration
  hosts: lab
  become: true

  tasks:
    - name: Read inventory information
      ansible.builtin.command: cat /opt/ansible-inventory-lab/info.txt
      register: inventory_info
      changed_when: false

    - name: Display inventory information
      ansible.builtin.debug:
        var: inventory_info.stdout

Save the file and execute:

ansible-playbook -i inventory verify.yml

Expected Result

Your existing ansible-client container should contain:

/opt/ansible-inventory-lab/
└── info.txt

The information file should contain:

Managed by Ansible Inventory
Host: ansible-client

Why Do We Use Ansible Inventory?

We use Ansible Inventory to centrally define and organize the systems that Ansible manages.

In enterprise DevOps environments, infrastructure may contain many servers distributed across development, testing, staging, and production environments.

Inventory allows us to group these systems logically and target specific hosts without hardcoding server addresses into every playbook.

For example, a playbook can target a particular inventory group, allowing the same automation to be reused against different environments by selecting the appropriate inventory.

This makes infrastructure automation easier to organize, scale, and maintain.
