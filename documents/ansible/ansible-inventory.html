Ansible Inventory

Ansible Inventory defines the managed hosts and groups of hosts that Ansible can connect to and configure. It tells Ansible which systems are available for automation.

1. Understand Your Lab Environment

Your current lab has two containers:

  • ansible-controller: Runs Ansible playbooks.
  • ansible-client: The managed Ubuntu container.

Ansible runs from the controller and connects to the client using SSH.

The inventory tells Ansible which host it should manage.

Lab restriction: All practical examples in this lesson use your existing ansible-client. No additional hosts or containers are required.

2. What Is an Ansible Inventory?

An inventory is a file or external data source containing information about managed hosts.

Inventory Type Description
Static Inventory Hosts are manually defined in a file.
Dynamic Inventory Hosts are discovered from external sources such as cloud platforms or infrastructure systems.

We will use a static inventory file in INI format.

3. Create the Inventory File

Create a project directory on your Ansible controller:

mkdir -p inventory-project
cd inventory-project

Command explanation:

Component Purpose
mkdir Creates a directory.
-p Creates parent directories if required and does not report an error if the directory already exists.
inventory-project Name of the directory being created.
cd Changes the current working directory.

Create the inventory file using the vi editor:

vi inventory

Press i to enter INSERT mode and add:

[lab]
ansible-client ansible_user=root

[ubuntu]
ansible-client

[all:vars]
ansible_connection=ssh
ansible_port=22

Press Esc, type :wq, and press Enter.

Inventory configuration explained:

Entry Purpose
[lab] Defines an inventory group named lab.
ansible-client Identifies your existing managed Ubuntu container.
ansible_user=root Specifies the SSH username.
[ubuntu] Defines another group containing the same client.
[all:vars] Defines variables inherited by all inventory hosts.
ansible_connection=ssh Specifies SSH as the connection method.
ansible_port=22 Specifies SSH port 22.
Important: Both groups contain the same ansible-client. This does not create additional containers or machines.

4. Understand Inventory Groups

Groups allow you to organize managed hosts by purpose or environment.

Your inventory contains two groups:

[lab]
ansible-client

[ubuntu]
ansible-client

The same host can belong to multiple groups.

You can target the client through either group:

hosts: lab

Or:

hosts: ubuntu

5. Understand Host and Group Variables

You can define connection variables directly beside a host entry:

[lab]
ansible-client ansible_user=root ansible_port=22

Common inventory variables:

Variable Purpose
ansible_host IP address or hostname used for the connection.
ansible_user SSH username.
ansible_port SSH port.
ansible_ssh_private_key_file Path to the SSH private key.
ansible_connection Connection type used by Ansible.

Group variables are defined using the group name followed by :vars.

[lab]
ansible-client

[lab:vars]
ansible_user=root
ansible_port=22

These variables apply to the hosts belonging to the lab group.

Security: Do not store private key contents or plaintext passwords in inventory files. Use Ansible Vault or an appropriate secrets-management solution for sensitive information.

6. Understand the --graph Option

The --graph option displays inventory groups and their hosts in a tree-like structure.

Execute:

ansible-inventory -i inventory --graph

Command breakdown:

Component Meaning
ansible-inventory Runs the Ansible inventory utility.
-i Short option used to specify an inventory source.
inventory The inventory filename being read.
--graph Displays inventory groups and hosts as a tree.

Expected output:

@all:
  |--@lab:
  |  |--ansible-client
  |--@ubuntu:
  |  |--ansible-client
  |--@ungrouped:

Understanding the output:

  • @all represents the built-in group containing all inventory hosts.
  • @lab represents your lab group.
  • @ubuntu represents your ubuntu group.
  • ansible-client appears under both groups because it belongs to both.
  • @ungrouped represents hosts that do not belong to any user-defined group. It is empty in this inventory.
Remember: --graph only displays the inventory structure. It does not connect to the client or execute a playbook.

7. Understand the --list Option

The --list option displays inventory information in JSON format.

Execute:

ansible-inventory -i inventory --list

Command breakdown:

Component Meaning
ansible-inventory Runs the inventory utility.
-i Specifies the inventory source.
inventory The inventory file to read.
--list Displays all inventory groups, hosts, and associated variables as JSON.

Expected output structure:

{
    "_meta": {
        "hostvars": {
            "ansible-client": {
                "ansible_connection": "ssh",
                "ansible_port": 22,
                "ansible_user": "root"
            }
        }
    },
    "all": {
        "children": [
            "lab",
            "ubuntu",
            "ungrouped"
        ]
    },
    "lab": {
        "hosts": [
            "ansible-client"
        ]
    },
    "ubuntu": {
        "hosts": [
            "ansible-client"
        ]
    }
}

The exact formatting and metadata can vary with the Ansible version and inventory configuration.

8. Understand the --host Option

The --host option displays inventory variables associated with a specific host.

Execute:

ansible-inventory -i inventory --host ansible-client

Command breakdown:

Component Meaning
ansible-inventory Runs the inventory utility.
-i inventory Loads the specified inventory file.
--host Requests variables for one inventory host.
ansible-client The inventory hostname whose variables are displayed.

Expected output:

{
    "ansible_connection": "ssh",
    "ansible_port": 22,
    "ansible_user": "root"
}

This command displays inventory data. It does not establish an SSH connection.

9. Test Connectivity Using the Ping Module

Execute:

ansible lab -i inventory -m ansible.builtin.ping

Command breakdown:

Component Meaning
ansible Runs the Ansible ad-hoc command utility.
lab Target inventory group.
-i inventory Specifies which inventory file to use.
-m Specifies the module to execute.
ansible.builtin.ping Tests Ansible connectivity and Python availability on the managed host.

Expected output:

ansible-client | SUCCESS => {
    "changed": false,
    "ping": "pong"
}
Important: Ansible's ping module is not an ICMP ping. It verifies that Ansible can communicate with the managed host and execute its module.

10. Create a Playbook Using the Inventory

Create a file named main.yml:

vi main.yml

Press i and add:

---
- name: Test Ansible inventory
  hosts: lab
  become: true

  tasks:
    - name: Display managed hostname
      ansible.builtin.command: hostname
      register: host_output
      changed_when: false

    - name: Display hostname result
      ansible.builtin.debug:
        var: host_output.stdout

Press Esc, type :wq, and press Enter.

Execute:

ansible-playbook -i inventory main.yml

Command breakdown:

Component Meaning
ansible-playbook Runs an Ansible playbook.
-i Specifies the inventory source.
inventory The inventory filename.
main.yml The playbook to execute.

Expected result: The playbook executes against your existing ansible-client and displays its hostname.

11. Understand Common Command Options

Option Purpose
-i Specifies an inventory file or inventory source.
-m Specifies a module for an ad-hoc command.
-a Provides arguments to an ad-hoc module.
-e Passes extra variables to a playbook or ad-hoc command.
-v Enables verbose output.
-vvv Enables more detailed verbose output.
--check Runs a playbook in check mode where supported, simulating changes where possible.
--diff Displays file differences for supported tasks.
--list-hosts Displays the hosts selected by a playbook without executing its tasks.
--syntax-check Checks playbook syntax without executing tasks.

12. Practical Project: Manage Your Ubuntu Client Through Inventory

Objective

Create an inventory file for your existing Ubuntu container and execute a playbook against the single managed client.

Project structure:

inventory-project/
├── inventory
└── main.yml

Step 1: Create the project directory

mkdir -p inventory-project
cd inventory-project

Step 2: Create the inventory file

vi inventory

Press i and add:

[lab]
ansible-client ansible_user=root

[ubuntu]
ansible-client

[all:vars]
ansible_connection=ssh
ansible_port=22

Save using Esc, :wq, and Enter.

Step 3: Display the inventory tree

ansible-inventory -i inventory --graph

Step 4: Test connectivity

ansible lab -i inventory -m ansible.builtin.ping

Step 5: Create the playbook

vi main.yml

Press i and add:

---
- name: Configure Ubuntu lab client
  hosts: lab
  become: true

  tasks:
    - name: Create lab directory
      ansible.builtin.file:
        path: /opt/ansible-inventory-lab
        state: directory
        mode: '0755'

    - name: Create inventory information file
      ansible.builtin.copy:
        dest: /opt/ansible-inventory-lab/info.txt
        content: |
          Managed by Ansible Inventory
          Host: {{ inventory_hostname }}
        mode: '0644'

    - name: Read inventory information
      ansible.builtin.command: cat /opt/ansible-inventory-lab/info.txt
      register: inventory_info
      changed_when: false

    - name: Display inventory information
      ansible.builtin.debug:
        var: inventory_info.stdout

Save the file using Esc, :wq, and Enter.

Step 6: Check playbook syntax

ansible-playbook -i inventory main.yml --syntax-check

Command breakdown:

Component Purpose
ansible-playbook Runs the playbook utility.
-i inventory Loads your inventory file.
main.yml Specifies the playbook.
--syntax-check Checks YAML and Ansible playbook syntax without executing tasks.

Step 7: Display selected hosts without executing tasks

ansible-playbook -i inventory main.yml --list-hosts

Command breakdown:

Component Purpose
--list-hosts Displays which hosts match the playbook's hosts pattern.

Expected output:

playbook: main.yml

  play #1 (lab): Configure Ubuntu lab client
    pattern: ['lab']
    hosts (1):
      ansible-client

Step 8: Execute the playbook

ansible-playbook -i inventory main.yml

Step 9: Verify the result

Create a verification playbook:

vi verify.yml

Add:

---
- name: Verify inventory configuration
  hosts: lab
  become: true

  tasks:
    - name: Read inventory information
      ansible.builtin.command: cat /opt/ansible-inventory-lab/info.txt
      register: inventory_info
      changed_when: false

    - name: Display inventory information
      ansible.builtin.debug:
        var: inventory_info.stdout

Save and execute:

ansible-playbook -i inventory verify.yml

Expected Result

Your existing ansible-client container should contain:

/opt/ansible-inventory-lab/
└── info.txt

The information file should contain:

Managed by Ansible Inventory
Host: ansible-client

13. Important Points

  • Inventory identifies the hosts managed by Ansible.
  • Static inventory can use INI or YAML formats.
  • Hosts can belong to multiple groups.
  • Host and group variables define connection and configuration details.
  • -i selects the inventory source.
  • --graph displays inventory groups and hosts as a tree.
  • --list displays inventory data in JSON format.
  • --host displays variables for a specific host.
  • --list-hosts displays hosts selected by a playbook.
  • --syntax-check checks playbook syntax.

Why Do We Use Ansible Inventory?

We use Ansible Inventory to centrally define and organize the systems that Ansible manages.

In enterprise DevOps environments, infrastructure may contain many servers distributed across development, testing, staging, and production environments.

Inventory allows us to group these systems logically and target specific hosts without hardcoding server addresses into every playbook.

For example, a playbook can target a particular inventory group, allowing the same automation to be reused against different environments by selecting the appropriate inventory.

This makes infrastructure automation easier to organize, scale, and maintain.
