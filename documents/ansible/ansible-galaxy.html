Ansible Galaxy

Ansible Galaxy is a platform and command-line tool for finding, sharing, installing, and managing reusable Ansible content such as roles and collections.

1. What Is Ansible Galaxy?

Imagine you need to configure Nginx on multiple servers. You could write all the automation tasks yourself, or you could find an existing reusable role created by another Ansible developer.

Ansible Galaxy provides a central place to discover and share this type of automation content.

It also provides the ansible-galaxy command, which you can use from your Ansible controller to manage roles and collections.

2. Understanding Roles and Collections

Content Description
Role A reusable directory structure containing tasks, handlers, variables, templates, and files.
Collection A packaged distribution of Ansible content that can include roles, modules, plugins, and playbooks.
Important: Roles and collections are different types of Ansible content. A collection can contain multiple roles and plugins.

3. Check Ansible Galaxy Command

Run this command on your Ansible controller:

ansible-galaxy --version

To view the available command options:

ansible-galaxy --help

4. Search for Roles

You can search Ansible Galaxy for reusable roles.

Example:

ansible-galaxy search nginx

You can also search for roles related to Docker:

ansible-galaxy search docker

The search results help you identify roles available for installation.

Note: Search results, role names, and available versions depend on the Galaxy service and its current content. Review a role's documentation, supported platforms, dependencies, and source repository before using it.

5. Install a Role from Ansible Galaxy

You can install a role by specifying its Galaxy namespace and role name.

Example:

ansible-galaxy role install geerlingguy.nginx

By default, Ansible installs the role into its configured roles path.

To install a role into a specific directory:

ansible-galaxy role install geerlingguy.nginx \
  -p ./roles

The project directory may look like this:

ansible-project/
├── main.yml
└── roles/
    └── geerlingguy.nginx/
        ├── defaults/
        ├── handlers/
        ├── tasks/
        ├── templates/
        └── vars/

6. List Installed Roles

To view the roles installed in the configured roles paths:

ansible-galaxy role list

To list roles from a specific directory:

ansible-galaxy role list -p ./roles

7. Use an Installed Role in a Playbook

After installing a role, you can reference it from your playbook.

main.yml

---
- name: Configure webserver
  hosts: ansible-client
  become: true

  roles:
    - geerlingguy.nginx

Ansible looks for the role in its configured role search paths.

Container limitation: The example Nginx role may require a service manager or other operating-system capabilities that are not available in your Ubuntu container. Installing a role does not guarantee that every task in it can run successfully inside a container.

8. Install Roles Using requirements.yml

In real projects, you may need multiple roles. Instead of installing them individually, you can define them in a requirements file.

Create a file named requirements.yml.

---
roles:
  - name: geerlingguy.nginx
    version: "3.2.0"

Install the roles defined in the requirements file:

ansible-galaxy role install -r requirements.yml -p ./roles

This downloads the specified role into the local roles/ directory.

9. Install Ansible Collections

Ansible Galaxy also distributes collections. Collections can contain modules, plugins, roles, and other Ansible content.

For example, install the community general collection:

ansible-galaxy collection install community.general

To install a collection into a specific project directory:

ansible-galaxy collection install community.general \
  -p ./collections

List installed collections:

ansible-galaxy collection list

Use a module from the collection in a playbook by specifying its fully qualified collection name.

---
- name: Collection example
  hosts: ansible-client
  become: true

  tasks:
    - name: Display a message
      ansible.builtin.debug:
        msg: "Ansible collection example"

The example uses a built-in module. A collection module would use its own namespace, collection name, and module name.

10. Install Collections Using requirements.yml

You can also define collections in a requirements file.

---
collections:
  - name: community.general
    version: "10.0.0"

Install the specified collections:

ansible-galaxy collection install -r requirements.yml

You can define both roles and collections in the same requirements file:

---
roles:
  - name: geerlingguy.nginx
    version: "3.2.0"

collections:
  - name: community.general
    version: "10.0.0"

Install both types of content:

ansible-galaxy install -r requirements.yml

11. Remove an Installed Role

To remove an installed role:

ansible-galaxy role remove geerlingguy.nginx

To remove an installed collection:

ansible-galaxy collection remove community.general

Removing a role or collection affects the installed content in the relevant Ansible paths.

12. Important Ansible Galaxy Commands

Command Purpose
ansible-galaxy --version Display command version information.
ansible-galaxy search nginx Search for roles.
ansible-galaxy role init myrole Create a new role structure.
ansible-galaxy role install role_name Install a role.
ansible-galaxy role list List installed roles.
ansible-galaxy role remove role_name Remove an installed role.
ansible-galaxy collection install namespace.collection Install a collection.
ansible-galaxy collection list List installed collections.
ansible-galaxy collection remove namespace.collection Remove an installed collection.

13. Practical Project: Manage Project Dependencies

Objective

Create a project that uses a requirements file to manage external Ansible roles and collections.

Project structure:

galaxy-project/
├── requirements.yml
├── main.yml
├── inventory
├── roles/
└── collections/

Step 1: Create requirements.yml

---
roles:
  - name: geerlingguy.nginx
    version: "3.2.0"

collections:
  - name: community.general
    version: "10.0.0"

Step 2: Install the dependencies

ansible-galaxy install -r requirements.yml

Step 3: List installed roles

ansible-galaxy role list

Step 4: List installed collections

ansible-galaxy collection list

Step 5: Create a main playbook

---
- name: Test Ansible project
  hosts: ansible-client
  become: true

  tasks:
    - name: Verify Ansible execution
      ansible.builtin.debug:
        msg: "Ansible Galaxy dependencies are ready"

Step 6: Execute the playbook

ansible-playbook main.yml

Expected Result

The project should have its external roles and collections installed, and the test playbook should execute successfully against the Ubuntu client.

Why Do We Use Ansible Galaxy?

We use Ansible Galaxy to discover, share, and reuse automation content instead of creating every component from scratch.

In enterprise DevOps environments, teams often need common automation for web servers, databases, cloud platforms, monitoring, and security configuration.

Rather than repeatedly developing the same automation, teams can use existing roles and collections, review them, pin specific versions, and manage dependencies through requirements files.

This improves consistency across environments and makes automation projects easier to maintain and distribute.

However, external roles and collections should always be reviewed for security, compatibility, supported versions, and maintenance status before being used in production.
