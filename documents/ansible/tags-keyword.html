Ansible Tags Keyword

The tags keyword allows you to assign labels to Ansible tasks. You can use these labels to execute selected tasks instead of running the entire playbook.

1. Why Do We Need Tags?

Imagine that you have an application deployment playbook containing the following operations:

  • Install application packages.
  • Create application directories.
  • Configure application files.
  • Create application users.
  • Validate the deployment.

Normally, running the playbook executes all applicable tasks. But what if you only want to execute the configuration tasks?

You can assign tags to individual tasks and execute only the tasks associated with a particular tag.

2. Basic Syntax

- name: Task description
  ansible.builtin.module_name:
    parameter: value
  tags:
    - configuration

The tags keyword is placed at the same indentation level as the module and its parameters.

3. Assign Tags to Individual Tasks

You can assign different tags to different tasks in the same playbook. 

---
- name: Application deployment
  hosts: ansible-client
  become: true

  tasks:
    - name: Install application packages
      ansible.builtin.apt:
        name: curl
        state: present
      tags:
        - installation

    - name: Create application directory
      ansible.builtin.file:
        path: /opt/myapp
        state: directory
        mode: '0755'
      tags:
        - configuration

    - name: Create application configuration
      ansible.builtin.copy:
        content: "APP_PORT=8080\n"
        dest: /opt/myapp/app.conf
        mode: '0644'
      tags:
        - configuration

    - name: Validate application directory
      ansible.builtin.command:
        cmd: test -d /opt/myapp
      changed_when: false
      tags:
        - validation

This playbook contains three tags:

Tag Tasks
installation Install application packages
configuration Create directory and configuration file
validation Validate application directory

4. Execute a Specific Tag Using --tags

The --tags option allows you to execute tasks associated with a particular tag.

To execute only installation tasks: 

ansible-playbook application.yml --tags installation

To execute only configuration tasks: 

ansible-playbook application.yml --tags configuration

To execute only validation tasks: 

ansible-playbook application.yml --tags validation

You can also execute multiple tags in one command: 

ansible-playbook application.yml --tags "installation,configuration"

In this example, Ansible executes tasks tagged with either installation or configuration.

5. Skip Specific Tags Using --skip-tags

Sometimes you want to execute most of the playbook but skip a particular category of tasks.

The --skip-tags option allows you to exclude tasks associated with specified tags. 

ansible-playbook application.yml --skip-tags validation

This executes the applicable tasks except those tagged with validation.

You can skip multiple tags: 

ansible-playbook application.yml --skip-tags "installation,validation"

6. Assign Multiple Tags to One Task

A single task can have multiple tags. This allows the same task to be selected through different tag names. 

---
- name: Application configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directory
      ansible.builtin.file:
        path: /opt/myapp
        state: directory
      tags:
        - configuration
        - application
        - deployment

You can execute this task using any one of its tags: 

ansible-playbook application.yml --tags configuration

ansible-playbook application.yml --tags application

ansible-playbook application.yml --tags deployment

7. Assign Tags to a Block

You can assign a tag to an entire block. The tag is inherited by the tasks inside that block. 

---
- name: Application setup
  hosts: ansible-client
  become: true

  tasks:
    - name: Configure application
      tags:
        - application_setup
      block:

        - name: Create application directory
          ansible.builtin.file:
            path: /opt/myapp
            state: directory

        - name: Create configuration file
          ansible.builtin.copy:
            content: "APP_PORT=8080\n"
            dest: /opt/myapp/app.conf

        - name: Display completion
          ansible.builtin.debug:
            msg: "Application setup completed"

All tasks inside this block inherit the application_setup tag.

Execute the block using: 

ansible-playbook application.yml --tags application_setup

8. Special Tags: always and never

Ansible provides special tags that control task selection. Two important special tags are always and never.

always

A task tagged with always normally executes even when you select a different tag. 

---
- name: Demonstrate always tag
  hosts: ansible-client
  become: true

  tasks:
    - name: Display application information
      ansible.builtin.debug:
        msg: "Application information"
      tags:
        - always

    - name: Install package
      ansible.builtin.apt:
        name: curl
        state: present
      tags:
        - installation

When you run: 

ansible-playbook application.yml --tags installation

The installation task executes, and the task tagged always normally executes as well.

never

A task tagged with never is skipped during a normal playbook run. It executes only when you explicitly select its tag or another applicable tag assigned to that task. 

---
- name: Demonstrate never tag
  hosts: ansible-client
  become: true

  tasks:
    - name: Display diagnostic information
      ansible.builtin.debug:
        msg: "Diagnostic task executed"
      tags:
        - never
        - diagnostics

    - name: Display normal task
      ansible.builtin.debug:
        msg: "Normal task executed"

Normal execution: 

ansible-playbook application.yml

The diagnostic task is skipped, while the normal task executes.

Execute the diagnostic task explicitly: 

ansible-playbook application.yml --tags diagnostics
Important: Special tags have selection behavior that differs from ordinary tags. A task tagged with never can still execute if another tag assigned to that task is selected.

9. List Available Tags

You can inspect the tags defined in a playbook without executing the tasks. 

ansible-playbook application.yml --list-tags

Ansible displays the available tags for the playbook.

10. List Tasks Associated With Tags

You can also list the tasks that would be selected by a tag. 

ansible-playbook application.yml --list-tasks --tags configuration

This displays the tasks selected by the configuration tag without executing them.

11. Important Rules About Tags

  • Tags are labels assigned to tasks, blocks, plays, or roles.
  • --tags selects tasks associated with specified tags.
  • --skip-tags excludes tasks associated with specified tags.
  • A task can have multiple tags.
  • Block-level tags are inherited by tasks inside the block.
  • always is a special tag that normally executes regardless of ordinary tag selection.
  • never prevents normal execution unless an applicable tag is explicitly selected.
  • --list-tags displays available tags.
  • --list-tasks displays selected tasks without executing them.

12. Practical Lab: Selectively Execute Application Tasks

Scenario

You are managing an application server. Your playbook contains installation, configuration, user creation, and validation tasks. You must be able to execute each category independently.

Create this playbook:

---
- name: Application management
  hosts: ansible-client
  become: true

  tasks:
    - name: Install required package
      ansible.builtin.apt:
        name: curl
        state: present
        update_cache: true
      tags:
        - installation

    - name: Create application directory
      ansible.builtin.file:
        path: /opt/learning-labs
        state: directory
        mode: '0755'
      tags:
        - configuration

    - name: Create application configuration
      ansible.builtin.copy:
        content: |
          APP_NAME=learning-labs
          APP_PORT=8080
          APP_ENV=production
        dest: /opt/learning-labs/app.conf
        mode: '0644'
      tags:
        - configuration

    - name: Create application user
      ansible.builtin.user:
        name: labuser
        state: present
      tags:
        - users

    - name: Validate application directory
      ansible.builtin.command:
        cmd: test -d /opt/learning-labs
      changed_when: false
      tags:
        - validation

    - name: Display execution information
      ansible.builtin.debug:
        msg: "Application management playbook started"
      tags:
        - always

Run the following commands from ansible-controller

1. List available tags:

ansible-playbook application-tags.yml --list-tags

2. List tasks for configuration:

ansible-playbook application-tags.yml --list-tasks --tags configuration

3. Install packages only:

ansible-playbook application-tags.yml --tags installation

4. Configure the application only:

ansible-playbook application-tags.yml --tags configuration

5. Create the application user only:

ansible-playbook application-tags.yml --tags users

6. Execute validation only:

ansible-playbook application-tags.yml --tags validation

7. Skip installation:

ansible-playbook application-tags.yml --skip-tags installation

Expected behavior:

  • Each tag selects its corresponding tasks.
  • Tasks with the always tag normally execute with tag selection.
  • Skipped categories do not execute.
  • You can inspect selected tasks before running them.

Why Do We Use Ansible Tags?

In real DevOps environments, playbooks can contain hundreds of tasks covering package installation, configuration management, user administration, application deployment, and validation.

Running every task during every execution is not always necessary. For example, if you only need to update an application configuration, you should not need to execute unrelated package installation or user creation tasks.

Ansible tags allow you to divide a playbook into logical execution categories. You can select the required tasks using --tags or exclude specific categories using --skip-tags.

This makes large playbooks easier to operate and maintain. It is particularly useful for Day 2 operations, where administrators may need to perform a specific activity without repeating the entire deployment workflow.
