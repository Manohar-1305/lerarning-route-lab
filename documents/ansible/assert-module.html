Ansible Assert Module

The Ansible Assert module validates conditions during playbook execution. It checks whether specified expressions are true and stops execution when an assertion fails.

1. What Is the Assert Module?

The ansible.builtin.assert module is used to verify conditions and validate expected values in an Ansible playbook.

An assertion is a condition that Ansible evaluates during execution. If the condition is true, the task succeeds. If the condition is false, the task fails and displays an error message.

Common use cases include:

  • Checking whether a required variable is defined.
  • Validating application configuration values.
  • Checking whether a port number is within an expected range.
  • Validating operating system requirements.
  • Checking available memory or disk capacity.
  • Verifying deployment prerequisites.
  • Preventing deployment when required conditions are not satisfied.

2. How Does the Assert Module Work?

             Ansible Controller
             ------------------
                    |
                    |
                Playbook
                    |
                    v
             Assert Task
                    |
                    v
             Evaluate Condition
                    |
             +------+------+
             |             |
          TRUE           FALSE
             |             |
             v             v
          SUCCESS        FAILURE
             |             |
             v             v
       Continue Tasks   Stop Execution

The Assert module evaluates one or more expressions. Every expression must evaluate to true for the assertion task to succeed.

3. Basic Assert Syntax

The basic syntax uses the that parameter to define the conditions that must be satisfied. 

---
- name: Validate application configuration
  hosts: ansible-client
  become: true

  tasks:
    - name: Validate application port
      ansible.builtin.assert:
        that:
          - application_port == 8080

In this example, Ansible checks whether application_port equals 8080.

4. Important Assert Parameters

Parameter Description
that Contains the condition or list of conditions that must be true.
fail_msg Custom message displayed when an assertion fails.
success_msg Custom message displayed when all assertions succeed.
quiet Suppresses normal assertion output when set to true.

5. Validate a Variable

You can use Assert to check whether a variable contains the expected value.

Playbook: assert-variable.yml

---
- name: Validate application variable
  hosts: ansible-client
  become: true

  vars:
    application_name: learning-labs

  tasks:
    - name: Validate application name
      ansible.builtin.assert:
        that:
          - application_name == "learning-labs"
        success_msg: "Application name is valid."
        fail_msg: "Application name is incorrect."

If the variable contains the expected value, the task succeeds. Otherwise, Ansible reports the failure message.

6. Validate Multiple Conditions

The that parameter accepts multiple expressions. All expressions must be true for the task to succeed.

Playbook: assert-multiple.yml

---
- name: Validate multiple application settings
  hosts: ansible-client
  become: true

  vars:
    application_name: learning-labs
    application_port: 8080
    application_environment: production

  tasks:
    - name: Validate application configuration
      ansible.builtin.assert:
        that:
          - application_name == "learning-labs"
          - application_port == 8080
          - application_environment == "production"
        success_msg: "All application settings are valid."
        fail_msg: "One or more application settings are invalid."

If even one condition is false, the assertion task fails.

7. Validate Whether a Variable Is Defined

A variable may be required for a playbook to work correctly. You can check whether it has been defined before using it.

Playbook: assert-defined.yml

---
- name: Validate required variables
  hosts: ansible-client
  become: true

  vars:
    application_name: learning-labs

  tasks:
    - name: Check whether application name is defined
      ansible.builtin.assert:
        that:
          - application_name is defined
        success_msg: "Application name is defined."
        fail_msg: "Application name is missing."

The Jinja2 test is defined checks whether a variable exists in the current Ansible variable context.

8. Validate Variable Data Types

You can use Jinja2 tests to validate the type of a variable. For example, an application port should be an integer.

Playbook: assert-datatype.yml

---
- name: Validate variable data types
  hosts: ansible-client
  become: true

  vars:
    application_port: 8080

  tasks:
    - name: Check application port data type
      ansible.builtin.assert:
        that:
          - application_port is integer
        success_msg: "Application port is an integer."
        fail_msg: "Application port must be an integer."

9. Validate a Numeric Range

Assertions can check whether a numeric value falls within an acceptable range.

Playbook: assert-range.yml

---
- name: Validate application port range
  hosts: ansible-client
  become: true

  vars:
    application_port: 8080

  tasks:
    - name: Validate port range
      ansible.builtin.assert:
        that:
          - application_port >= 1
          - application_port <= 65535
        success_msg: "Application port is within the valid range."
        fail_msg: "Application port must be between 1 and 65535."

10. Validate a Linux Operating System

You can validate operating system facts before performing operating-system-specific tasks.

Playbook: assert-os.yml

---
- name: Validate operating system
  hosts: ansible-client
  become: true

  tasks:
    - name: Ensure target is Ubuntu
      ansible.builtin.assert:
        that:
          - ansible_distribution == "Ubuntu"
        success_msg: "Target operating system is Ubuntu."
        fail_msg: "This playbook requires Ubuntu."

The variable ansible_distribution is an Ansible fact gathered from the managed host.

11. Validate Available Memory

You can validate the available memory before deploying an application.

Playbook: assert-memory.yml

---
- name: Validate available memory
  hosts: ansible-client
  become: true

  tasks:
    - name: Ensure sufficient memory is available
      ansible.builtin.assert:
        that:
          - ansible_memtotal_mb >= 1024
        success_msg: "Memory requirement satisfied."
        fail_msg: "At least 1 GB of total memory is required."

The fact ansible_memtotal_mb represents total detected memory in megabytes. It does not represent currently available memory.

12. Use Assert with Custom Messages

The success_msg and fail_msg parameters make assertion results easier to understand.

Playbook: assert-messages.yml

---
- name: Validate deployment requirements
  hosts: ansible-client
  become: true

  vars:
    deployment_environment: production

  tasks:
    - name: Validate deployment environment
      ansible.builtin.assert:
        that:
          - deployment_environment in ["development", "testing", "production"]
        success_msg: "Deployment environment is supported."
        fail_msg: "Unsupported deployment environment."

13. Suppress Assertion Output Using Quiet

The quiet parameter suppresses normal assertion output. Assertion failures are still reported.

Playbook: assert-quiet.yml

---
- name: Validate configuration quietly
  hosts: ansible-client
  become: true

  vars:
    application_port: 8080

  tasks:
    - name: Validate application port
      ansible.builtin.assert:
        that:
          - application_port == 8080
        quiet: true

14. Practical Project: Validate Application Deployment Requirements

Project Objective

Create a pre-deployment validation playbook that checks whether the managed host and application configuration satisfy the deployment requirements.

Requirements:
  1. Verify that the target operating system is Ubuntu.
  2. Validate the application name.
  3. Validate the application port.
  4. Verify that the application environment is supported.
  5. Ensure the target has at least 1 GB of total memory.
  6. Display meaningful success or failure messages.
Project playbook: validate-deployment.yml 
---
- name: Validate application deployment requirements
  hosts: ansible-client
  become: true

  vars:
    application_name: learning-labs
    application_port: 8080
    application_environment: production

  tasks:
    - name: Validate operating system
      ansible.builtin.assert:
        that:
          - ansible_distribution == "Ubuntu"
        success_msg: "Operating system validation passed."
        fail_msg: "Deployment requires Ubuntu."

    - name: Validate application name
      ansible.builtin.assert:
        that:
          - application_name == "learning-labs"
        success_msg: "Application name validation passed."
        fail_msg: "Invalid application name."

    - name: Validate application port
      ansible.builtin.assert:
        that:
          - application_port is integer
          - application_port >= 1
          - application_port <= 65535
        success_msg: "Application port validation passed."
        fail_msg: "Invalid application port."

    - name: Validate deployment environment
      ansible.builtin.assert:
        that:
          - application_environment in ["development", "testing", "production"]
        success_msg: "Deployment environment validation passed."
        fail_msg: "Unsupported deployment environment."

    - name: Validate total memory
      ansible.builtin.assert:
        that:
          - ansible_memtotal_mb >= 1024
        success_msg: "Memory requirement satisfied."
        fail_msg: "At least 1 GB of total memory is required."

    - name: Display validation completion
      ansible.builtin.debug:
        msg: "All deployment prerequisites have passed."

15. Important Considerations

  • Every expression listed under that must evaluate to true.
  • Assertions are evaluated on the Ansible controller using the available variables and facts.
  • Facts must be gathered before validating fact variables.
  • Use is defined when checking whether a variable exists.
  • Use appropriate type checks before numeric comparisons.
  • An assertion failure normally stops execution for that host.
  • Use meaningful failure messages to make troubleshooting easier.
  • Assertions validate conditions; they do not modify files or configure the managed host.

Why Do We Use the Ansible Assert Module?

In production DevOps environments, running a deployment without checking its prerequisites can cause failures, inconsistent configurations and unnecessary downtime.

For example, an application may require Ubuntu, a specific port, a minimum amount of memory and a valid deployment environment. If these requirements are not satisfied, continuing with the deployment may lead to unexpected problems.

The Assert module allows engineers to validate these requirements before executing subsequent tasks. It provides a controlled way to stop a playbook when an expected condition is not satisfied.

It is commonly used in deployment validation, infrastructure automation, configuration verification and pre-deployment checks.
