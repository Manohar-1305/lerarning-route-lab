Ansible loop Keyword

The loop keyword allows you to execute the same Ansible task multiple times using a list of items. Instead of writing separate tasks for every item, you define one task and provide the values that Ansible should process.

1. Why Do We Need loop?

Imagine that you need to create five directories on a Linux server. Without a loop, you would write five separate tasks. 

tasks:
  - name: Create directory 1
    ansible.builtin.file:
      path: /opt/app1
      state: directory

  - name: Create directory 2
    ansible.builtin.file:
      path: /opt/app2
      state: directory

  - name: Create directory 3
    ansible.builtin.file:
      path: /opt/app3
      state: directory

This approach becomes difficult to maintain when the number of items increases.

Using loop, you can achieve the same result with one task.

2. Basic Syntax

- name: Task description
  ansible.builtin.module_name:
    parameter: value
  loop:
    - item1
    - item2
    - item3

Ansible executes the task once for each item in the list. The current item is available through the variable item.

3. Example: Create Multiple Directories

---
- name: Create application directories
  hosts: ansible-client
  become: true

  tasks:
    - name: Create directories
      ansible.builtin.file:
        path: "/opt/{{ item }}"
        state: directory
        mode: '0755'
      loop:
        - application
        - logs
        - backups
        - configuration

Ansible executes the file module four times:

Iteration item value Directory created
1application/opt/application
2logs/opt/logs
3backups/opt/backups
4configuration/opt/configuration

4. Example: Create Multiple Users

You can use the same loop to create multiple Linux users. 

---
- name: Create multiple Linux users
  hosts: ansible-client
  become: true

  tasks:
    - name: Create users
      ansible.builtin.user:
        name: "{{ item }}"
        state: present
      loop:
        - devuser
        - testuser
        - deployuser

The user module executes three times, creating each user if the account does not already exist.

5. Example: Install Multiple Packages

You can use a loop to install multiple packages using the APT module. 

---
- name: Install multiple packages
  hosts: ansible-client
  become: true

  tasks:
    - name: Install packages
      ansible.builtin.apt:
        name: "{{ item }}"
        state: present
        update_cache: true
      loop:
        - curl
        - wget
        - vim
        - tree

The APT task executes once for each package. Ansible ensures that each package is installed.

Practical note: Some Ansible modules, including APT, can accept a list of package names directly. A loop is useful when you need to perform separate operations or apply different task behavior to each item.

6. Example: Execute a Command for Each Item

You can also use loops with the command module. 

---
- name: Display multiple messages
  hosts: ansible-client
  become: true

  tasks:
    - name: Display application names
      ansible.builtin.command:
        cmd: "echo {{ item }}"
      loop:
        - frontend
        - backend
        - database
      changed_when: false

The command executes three times, once for each application name.

7. Example: Loop Through a List of File Paths

You can use loops to check whether multiple files exist. 

---
- name: Check application files
  hosts: ansible-client
  become: true

  tasks:
    - name: Check each file
      ansible.builtin.command:
        cmd: "test -f {{ item }}"
      loop:
        - /etc/hosts
        - /etc/passwd
        - /etc/group
      changed_when: false

Each file is checked separately. If any file does not exist, its task iteration returns a non-zero result and the task is reported as failed for that item.

8. Understanding item

The variable item represents the current value being processed by the loop. 

loop:
  - frontend
  - backend
  - database

During execution, Ansible assigns these values to item in sequence:

Iteration item
1frontend
2backend
3database

When the task runs for the first time, item contains frontend. In the next iteration, it contains backend, and finally database.

9. Important Points About loop

  • loop accepts a list of items.
  • The task executes once for every item.
  • item represents the current item.
  • You can use loops with modules such as file, user, group, apt, and command.
  • Each iteration uses the same task definition.
  • Loops reduce repetitive YAML and make playbooks easier to maintain.
Important: A loop does not automatically make a task successful. If an iteration fails, Ansible normally reports the failure and stops further execution for that host unless the failure is handled separately.

10. Practical Lab: Prepare an Application Environment

Scenario

You are preparing an application server. You need to create multiple directories, create multiple users, and install several packages using loops.

Create this playbook:

---
- name: Prepare application environment
  hosts: ansible-client
  become: true

  tasks:
    - name: Create application directories
      ansible.builtin.file:
        path: "/opt/{{ item }}"
        state: directory
        mode: '0755'
      loop:
        - frontend
        - backend
        - database
        - logs

    - name: Create application users
      ansible.builtin.user:
        name: "{{ item }}"
        state: present
      loop:
        - appadmin
        - appdeploy

    - name: Install required packages
      ansible.builtin.apt:
        name: "{{ item }}"
        state: present
        update_cache: true
      loop:
        - curl
        - wget
        - vim

    - name: Display completion message
      ansible.builtin.debug:
        msg: "Application environment preparation completed"

Run from ansible-controller:

ansible-playbook application-environment.yml

Expected behavior:

  • Four directories are created under /opt.
  • Two Linux users are created.
  • Three packages are installed.
  • The completion message is displayed.

Why Do We Use the Ansible loop Keyword?

In real DevOps environments, automation frequently involves performing the same operation on multiple resources. For example, you may need to create application directories, configure multiple users, install packages, or check several configuration files.

Writing a separate task for every resource makes playbooks longer and harder to maintain. When the number of resources changes, you must also update multiple task definitions.

The loop keyword solves this problem by allowing one task to process a list of values. Ansible automatically executes the task for each item.

This makes playbooks shorter, reusable, and easier to maintain. It is especially useful when managing multiple application components, Linux users, packages, directories, and configuration files across servers.
