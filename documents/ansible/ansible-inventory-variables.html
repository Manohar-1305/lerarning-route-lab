Ansible Inventory Variables

Inventory variables allow you to define configuration values for managed hosts and groups directly in separate variable files.

Instead of placing every variable inside an inventory file or playbook, you can organize them using group_vars and host_vars.

1. What Are Inventory Variables?

Inventory variables are values assigned to hosts or groups. Ansible makes these values available when executing playbooks against the matching hosts.

There are two important locations:

Directory Purpose
group_vars/ Stores variables shared by hosts belonging to a group.
host_vars/ Stores variables specific to an individual host.

2. Understanding the Project Structure

We will use the existing ansible-client managed host.

Create the following project structure on the Ansible controller:

ansible-inventory-lab/
├── inventory.yml
├── inventory-vars.yml
├── group_vars/
│   └── lab.yml
└── host_vars/
    └── ansible-client.yml

Each file has a separate responsibility:

  • inventory.yml defines the managed host and its group.
  • group_vars/lab.yml defines variables shared by the lab group.
  • host_vars/ansible-client.yml defines variables specifically for ansible-client.
  • inventory-vars.yml is the playbook that uses these variables.

3. Create the Inventory File

Create the project directory and move into it:

mkdir -p ansible-inventory-lab/group_vars
mkdir -p ansible-inventory-lab/host_vars
cd ansible-inventory-lab

Create the inventory file:

vi inventory.yml

Add the following configuration:

---
all:
  children:
    lab:
      hosts:
        ansible-client:
          ansible_user: root
          ansible_connection: ssh
          ansible_port: 22

Save the file using :wq.

4. Configure Group Variables

Group variables apply to every host belonging to the specified inventory group.

Create the group variable file:

vi group_vars/lab.yml

Add the following variables:

---
environment: training
application_name: learning-labs
application_port: 8080
package_name: curl

Save the file using :wq.

Understanding the Variables

Variable Value Purpose
environment training Identifies the environment.
application_name learning-labs Defines the application name.
application_port 8080 Defines the application port.
package_name curl Defines the package to install.

5. Configure Host Variables

Host variables apply only to the specific managed host. They can override values inherited from its inventory groups.

Create the host variable file:

vi host_vars/ansible-client.yml

Add the following configuration:

---
environment: development
server_role: application-server
server_owner: devops-team

Save the file using :wq.

Important: The environment variable is defined in both the group and host variable files. Since host variables have higher precedence than group variables, the effective value for ansible-client will be development.

6. Understand Variable Precedence

When the same variable is defined at multiple inventory levels, Ansible uses variable precedence rules to determine the effective value.

For the inventory variables covered in this lesson:

Variable source Precedence
Group variables Lower
Host variables Higher

For example:

# group_vars/lab.yml

environment: training

# host_vars/ansible-client.yml

environment: development

Effective value:

environment: development

This is the inventory-level precedence relationship. Ansible has additional precedence levels involving playbook variables, task variables, extra variables, and other sources.

7. Create a Playbook to Use Inventory Variables

Create the playbook:

vi inventory-vars.yml

Add the following content:

---
- name: Demonstrate Inventory Variables
  hosts: ansible-client
  become: true

  tasks:
    - name: Display environment
      ansible.builtin.debug:
        msg: "Environment: {{ environment }}"

    - name: Display application name
      ansible.builtin.debug:
        msg: "Application: {{ application_name }}"

    - name: Display application port
      ansible.builtin.debug:
        msg: "Application Port: {{ application_port }}"

    - name: Display server role
      ansible.builtin.debug:
        msg: "Server Role: {{ server_role }}"

    - name: Display server owner
      ansible.builtin.debug:
        msg: "Server Owner: {{ server_owner }}"

    - name: Install package defined in group variables
      ansible.builtin.apt:
        name: "{{ package_name }}"
        state: present
        update_cache: true

What Happens During Execution?

  1. Ansible reads inventory.yml.
  2. Ansible identifies ansible-client as a member of the lab group.
  3. Ansible loads variables from group_vars/lab.yml.
  4. Ansible loads variables from host_vars/ansible-client.yml.
  5. Host-level environment overrides the group-level value.
  6. The playbook uses the resolved variables to execute its tasks.

8. Execute the Playbook

ansible-playbook -i inventory.yml inventory-vars.yml

Command breakdown:

Option / Argument Meaning
ansible-playbook Runs an Ansible playbook.
-i Specifies the inventory source.
inventory.yml The YAML inventory file.
inventory-vars.yml The playbook to execute.

The debug tasks should display values similar to:

Environment: development
Application: learning-labs
Application Port: 8080
Server Role: application-server
Server Owner: devops-team

The package installation task installs curl if it is not already installed.

Note: The recap and task status may differ depending on whether curl is already installed and whether the package cache needs updating.

9. Inspect Inventory Variables

Ansible provides the ansible-inventory command to inspect inventory information without executing a playbook.

Display the Inventory Graph

ansible-inventory -i inventory.yml --graph

Command breakdown:

  • ansible-inventory: Inspects inventory data.
  • -i inventory.yml: Loads the specified inventory file.
  • --graph: Displays groups and their host relationships in a tree-like format.

Display All Inventory Data

ansible-inventory -i inventory.yml --list

Command breakdown:

  • --list: Displays the inventory as JSON, including groups, hosts, and available host variables.

Display Variables for a Specific Host

ansible-inventory -i inventory.yml --host ansible-client

Command breakdown:

  • --host: Displays the variables associated with a particular inventory host.
  • ansible-client: The inventory hostname being inspected.

This command displays the resolved inventory variables for ansible-client. It does not connect to the managed host.

10. Practical Project: Environment-Specific Configuration

Objective

Use group and host variables to maintain different configuration values without modifying the playbook.

Step 1: Open the group variable file.

vi group_vars/lab.yml

Change the environment value:

environment: staging
application_name: learning-labs
application_port: 9090
package_name: curl

Step 2: Open the host variable file.

vi host_vars/ansible-client.yml

Change the environment value:

environment: production
server_role: application-server
server_owner: devops-team

Step 3: Execute the same playbook again.

ansible-playbook -i inventory.yml inventory-vars.yml

Expected result:

Environment: production
Application: learning-labs
Application Port: 9090
Server Role: application-server
Server Owner: devops-team

The playbook remains unchanged. Only the variable files have been modified.

Practice Tasks

  • Change the application port to 7070.
  • Change the server owner in the host variable file.
  • Run the playbook and verify the updated values.
  • Inspect the resolved variables using ansible-inventory --host.

Why Do We Use Ansible Inventory Variables?

In real-world DevOps environments, the same application is often deployed across development, staging, and production environments.

Each environment may require different configuration values, such as application ports, package names, environment labels, server roles, and ownership details.

Hardcoding these values inside playbooks makes maintenance difficult. Every environment change could require editing the playbook itself.

Inventory variables separate configuration data from automation logic. Group variables allow shared configuration, while host variables provide host-specific configuration.

This makes playbooks reusable, reduces duplication, and simplifies environment management.

Real-world example: A DevOps engineer can use the same deployment playbook for multiple environments while maintaining separate configuration values through inventory variable files.
